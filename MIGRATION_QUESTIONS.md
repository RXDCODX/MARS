## Вопрос 6. AC.R — 14 немигрированных наград: три архитектурных пробела

**Что нашлось.** Все 14 наград в монолите — подклассы `TemporaryReward`. Он делал
две вещи: (1) создавал и каждые 5 минут сверял награду в Twitch (название,
описание, цена, цвет, ввод пользователя, кулдауны), (2) подписывался на
редемпшен и вызывал логику механики. При переносе обе стороны разъехались:

- **Определения наград живут в таблице `ChannelRewards`.** Её наполняет
  `ChannelRewardsSyncService` (`MARS.TwitchCore`), каждые 2 минуты создавая в
  Twitch награду по строке таблицы. Строки приезжают из legacy-данных миграцией
  `20260930192800_SeedLegacyTwitch`. Награды, которых в таблице нет,
  `ChannelRewardsSyncService` не создаёт, а удаляет только помеченные
  `IsDeleted` — то есть без строки в таблице награда в Twitch не появится, и
  обработчик не получит ни одного события.
- **Условного включения нет.** В монолите `IsRewardEnabled` возвращал
  `DateTime.Now.DayOfWeek == DayOfWeek.Friday` (`4_FumoRoll/FumoFridayRoll`,
  `13_FumoFriday/FumoFriday`) и `== Monday` (`170_MikuMondayAlert`). У
  `ChannelRewardRecord` такого поля нет, синхронизатор берёт `IsEnabled` из
  строки как есть. Три награды из четырнадцати работают «только по дням недели».
- **Часть наград нуждается в API Twitch, которого нет в `MARS.Alerts`.**
  Обработчики наград живут в `MARS.Alerts` и ходят только в RabbitMQ; у них нет
  ни `ITwitchAPI`, ни клиента `MARS.TwitchCore`. Но `160_LegBum/LegBumRefundService`
  отменяет редемпшен через
  `ChannelPoints.UpdateRedemptionStatusAsync` и пишет в чат, а
  `4_SearchWife` ищет жену через `IWaifuLookupService` из `MARS.TwitchCore`.
- **Контракт оверлея проверить нечем.** Оверлей лежит вне репозитория
  (`mars.client` не переносился). Методы `ITelegramusNotifier`, оставшиеся без
  вызывающей стороны — `MakeScreenEmojisParticles`, `FumoFriday`, `MikuMonday`,
  `AllRefund`, `AudioQuizStart`/`AudioQuizStop` — приходят из перенесённого
  монолитного хаба, и правильность их payload сверять не с чем.

**Что нужно от вас.**

| | Что делать | Последствия |
|---|---|---|
| **A** | Добавить колонку «дни недели» в `ChannelRewardRecord` и научить `ChannelRewardsSyncService` её учитывать; определения новых наград — миграцией-сидом | Закрывает гейт по дням недели. Сид придётся писать на каждую награгу вручную |
| **B** | Определения новых наград создаёт оператор в панели Twitch вручную, в таблице появляется строка только для синхронизации кулдаунов и лимитов | Без миграций, но каждая награда требует ручного шага при развёртывании |
| **C** | Награды, которым нужен Twitch API, живут в `MARS.TwitchCore` как `TemporaryReward`-подобные подписчики, а `MARS.Alerts` получает только «послефактум»-события оверлея | Возвращает в репозиторий подписчики на EventSub; по сути частичный возврат монолитной схемы |
| **D** | Дать `MARS.Alerts` клиента `MARS.TwitchCore` (новый internal-эндпоинт для отмены редемпшена и отправки в чат) | Один новый контракт, зато обработчики остаются в одном месте |
