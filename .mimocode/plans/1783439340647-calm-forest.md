# Fix: `ICommandService.ParseParameters` drops words from multi-word string parameters

## Bug

`!sr achitects doomsday` only passes `"achitects"` as `query`, dropping `"doomsday"`.

### Root Cause

`ICommandService.cs:134-156` — the default interface method `ParseParameters` iterates over `commandInfo.Length` and assigns **one** `inputParts[i]` per parameter. For `SrCommand` (1 param `query`), only `inputParts[0]` is assigned; remaining parts are silently dropped.

**Correct implementation exists in `BaseCommand.ParseParameters` (lines 116-128):**
```csharp
if (param.Type == "string" && param == commandParameters.Last() && currentIndex < parts.Length - 1)
{
    var remainingParts = parts.Skip(currentIndex);
    parameters[param.Name] = string.Join(" ", remainingParts);
    break;
}
```

## Fix

### 1. Fix `ICommandService.ParseParameters` (ICommandService.cs:134-156)

Add the same tail-string join logic:

```csharp
Dictionary<string, object> ParseParameters(string input, CommandParameterInfo[]? commandInfo)
{
    var parameters = new Dictionary<string, object>(StringComparer.OrdinalIgnoreCase);

    var inputParts = string.IsNullOrWhiteSpace(input)
        ? Array.Empty<string>()
        : BaseCommand.ParseParametersWithQuotes(input);

    if (commandInfo is not null && commandInfo.Length > 0)
    {
        var lastParam = commandInfo[^1];
        for (var i = 0; i < commandInfo.Length; i++)
        {
            var p = commandInfo[i];
            if (i < inputParts.Length)
            {
                if (p == lastParam && p.Type == "string" && i < inputParts.Length - 1)
                {
                    parameters[p.Name] = string.Join(" ", inputParts.Skip(i));
                    break;
                }
                parameters[p.Name] = inputParts[i];
            }
        }
    }

    return parameters;
}
```
