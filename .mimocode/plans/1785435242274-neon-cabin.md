# План: TwitchClientProxy — прозрачное пересоздание ITwitchClient

## Проблема

После 12+ часов работы `TwitchClient` из TwitchLib превращается в "зомби" — отключается и не может восстановиться. Текущая реализация:

```csharp
services.AddSingleton<ITwitchClient>(sp =>
    sp.GetRequiredService<TwitchConnectionManager>().Client  // ссылка на конкретный экземпляр
);
```

DI возвращает ссылку на конкретный `TwitchClient`. Когда он ломается, `ConnectionManager` пытается reconnect того же сломанного экземпляра, но underlying transport уже мёртв. Пересоздать клиент невозможно — 50+ сервисов держат ссылку на старый.

## Решение: TwitchClientProxy (Adapter + Observer + Bridge)

### Архитектура

```
DI Container (Singleton)
  └── ITwitchClient → TwitchClientProxy (Adapter)
                          │
                          ├── _inner: ITwitchClient (volatile) ← можно заменить
                          ├── Event forwarding (Observer)
                          │     внешние подписчики → proxy → _inner
                          └── ReplaceClient() ← ConnectionManager вызывает
                                                    при пересоздании

TwitchConnectionManager (IHostedService)
  ├── Owns TwitchClientProxy
  ├── RecreateClientAsync(): dispose old → create new → proxy.ReplaceClient()
  └── Reconnect strategy: simple reconnect → full recreation
```

### Ключевые файлы

| Файл | Действие |
|------|----------|
| `Services/Twitch/Client/TwitchClientProxy.cs` | **СОЗДАТЬ** — новый Adapter/Proxy |
| `Services/Twitch/Client/TwitchConnectionManager.cs` | **ИЗМЕНИТЬ** — deep recreation + proxy |
| `StartupExstensions.cs` | **ИЗМЕНИТЬ** — DI регистрация через proxy |

### Изменения в потребителях: НЕТ. Ни один из 50+ сервисов не нужно менять.

## 1. TwitchClientProxy (новый файл)

**Путь**: `MARS.Projects/MARS.Server/Services/Twitch/Client/TwitchClientProxy.cs`

Реализует `ITwitchClient`, делегирует всё на `_inner`.

### Свойства (11 штук)
Все делегируются на `_inner` напрямую:
```csharp

public IReadOnlyList<JoinedChannel> JoinedChannels => _inner.JoinedChannels;
// ... остальные 9 свойств
```

### Методы (15 штук)
Все делегируются на `_inner` напрямую:
```csharp
public Task SendMessageAsync(JoinedChannel channel, string message, bool dryRun = false)
    => _inner.SendMessageAsync(channel, message, dryRun);
// ... остальные методы
```

### События (37 штук) — Observer Pattern

**5 основных событий** (используются в коде): полный forwarding через proxy.
- `OnMessageReceived` (16 подписчиков)
- `OnConnected` (2 подписчика)
- `OnDisconnected` (1 подписчик)
- `OnConnectionError` (1 подписчик)
- `OnMessageCleared` (1 подписчик)

Механизм forwarding:
```csharp
private readonly Dictionary<string, Delegate> _forwardingHandlers = new();
private readonly Dictionary<string, Delegate> _externalHandlers = new();

// При подписке на событие proxy:
// 1. Сохраняем handler в _externalHandlers
// 2. Если первая подписка на это событие — создаём forwarding handler
// 3. Forwarding handler подписывается на _inner.<Event>
// 4. При вызове forwarding handler — вызываем _externalHandlers[name]

// При ReplaceClient:
// 1. Отписываем все forwarding handlers от старого _inner
// 2. Подписываем все forwarding handlers на новый _inner
// 3. _externalHandlers не трогаем — подписчики остаются на proxy
```

**Остальные 32 события**: explicit interface implementation, делегирование на `_inner` напрямую (без forwarding). Никто не подписан — overhead нулевой.

### ReplaceClient — Bridge Pattern

```csharp
internal void ReplaceClient(ITwitchClient newClient)
{
    ITwitchClient? oldClient;
    lock (_swapLock)
    {
        oldClient = _inner;

        // 1. Отписываем forwarding от старого клиента
        foreach (var kvp in _forwardingHandlers)
            UnsubscribeFromInner(kvp.Key, kvp.Value);

        // 2. Заменяем inner
        _inner = newClient;

        // 3. Подписываем forwarding на новый клиент
        foreach (var kvp in _forwardingHandlers)
            SubscribeToInner(kvp.Key, kvp.Value);
    }

    // 4. Dispose старого клиента (вне lock, чтобы не блокировать)
    (oldClient as IDisposable)?.Dispose();
}
```

### Thread Safety
- `_inner` — `volatile` reference (lock-free reads при делегировании методов)
- `_swapLock` — protects `ReplaceClient` (редкая операция)
- Event add/remove — через `lock(_swapLock)` (совпадает с swap)

### Новая стратегия reconnect

Попытки 1-3: простой reconnect (текущее поведение).
Попытки 4+: **полное пересоздание** клиента.

```csharp
private async Task<bool> TryDeepRecreationAsync()
{
    // 1. Dispose старого клиента и transport
    await DisconnectSafelyAsync();
    (_transport as IDisposable)?.Dispose();

    // 2. Создать новый transport + client
    var config = _twitchOptions.CurrentValue;
    _transport = CreateTransportClient(config.TransportProtocol);
    _client = CreateTwitchClient(config.TransportProtocol);

    // 3. Atomic swap через proxy
    _proxy.ReplaceClient(_client);

    // 4. Re-wire events на новый _client
    WireEvents();

    // 5. Initialize + Connect
    _initialized = false;
    await EnsureInitializedAndConnected();

    return _client.IsConnected;
}
```

### Обновлённый ReconnectLoopAsync

```csharp
private async Task ReconnectLoopAsync(CancellationToken ct)
{
    while (!ct.IsCancellationRequested && _reconnectAttempts < MaxReconnectAttempts)
    {
        _reconnectAttempts++;
        var delay = CalculateReconnectDelay(_reconnectAttempts);
        await Task.Delay(delay, ct);

        if (_client.IsConnected) { ... return; }

        bool success;
        if (_reconnectAttempts <= 3)
        {
            // Простой reconnect
            success = await TrySimpleReconnectAsync();
        }
        else
        {
            // Полное пересоздание
            _logger.LogWarning("Simple reconnect failed {N} times, performing deep recreation", _reconnectAttempts - 1);
            success = await TryDeepRecreationAsync();
        }

        if (success) { ... return; }
    }
}
```

### WireEvents — привязка к _client

Метод `WireEvents()` теперь подписывается на `_client` напрямую (не на proxy). Это жизненно важно — менеджеру нужны события от реального клиента для мониторинга.

## 4. Edge Cases

| Сценарий | Решение |
|----------|---------|
| Сообщение отправляется во время swap | `SendMessageAsync` идёт на старый `_inner` (volatile read). Старый клиент ещё жив в этот момент — отправка пройдёт или бросит exception (потребитель обработает). |
| Event fires во время swap | Forwarding handler уже подписан на старый клиент. Новый forwarding будет подписан на новый. Потеря одного события возможна — acceptable. |
| Proxy создан, но _inner ещё не установлен | Конструктор `TwitchConnectionManager` вызывает `ReplaceClient` сразу после создания клиента. Proxy создаётся с пустым inner, но до `StartAsync` никто не использует ITwitchClient. |
| Dispose proxy | `TwitchConnectionManager.DisposeAsync` вызывает `StopAsync` → disconnect. Proxy не диспозится напрямую (он Singleton). |
