# План: Переработка отложенной записи DanbooruAutoPost для Telegram

## Проблема

Текущая реализация «отложенной записи» — одноразовая: `ScheduledAtUtc` на конфиге, после публикации конфиг отключается. Это не подходит для Telegram, где нужна **буферная очередь** постов на горизонт планирования.

Также: сервис код ссылается на `config.ScheduledAtUtc` которого нет на entity → ошибки компиляции.

## Решение

Заменить одноразовую `ScheduledAtUtc` на очередь `DanbooruScheduledPost` записей. Cron выражение определяет расписание, `PlanningHorizonDays` — горизонт заполнения буфера.

## Шаг 1: Entity и Database

### 1.1 — Добавить `ScheduledAtUtc` в `DanbooruAutoPostConfig.cs`
Файл: `MARS.Server/Services/DanbooruAutoPost/Entities/DanbooruAutoPostConfig.cs`

```csharp
public DateTime? ScheduledAtUtc { get; set; }
```

> Временно — для совместимости с миграцией `20260813080000`. Позже можно убрать, когда очередь заработает.

### 1.2 — Добавить навигационное свойство в `DanbooruAutoPostConfig.cs`
```csharp
public ICollection<DanbooruScheduledPost> ScheduledPosts { get; set; } = [];
```

### 1.3 — Регистрация `DanbooruScheduledPost` в `AppDbContext.cs`
Файл: `MARS.Server/DataBaseContext/AppDbContext.cs`

```csharp
public DbSet<DanbooruScheduledPost> DanbooruScheduledPosts { get; set; } = null!;
```

Конфигурация FK в `OnModelCreating`:
```csharp
modelBuilder.Entity<DanbooruScheduledPost>()
    .HasIndex(e => new { e.ConfigId, e.ScheduledAtUtc })
    .IsUnique();

modelBuilder.Entity<DanbooruScheduledPost>()
    .HasOne(e => e.Config)
    .WithMany(c => c.ScheduledPosts)
    .HasForeignKey(e => e.ConfigId)
    .OnDelete(DeleteBehavior.Cascade);
```

### 1.4 — Создать миграцию
```bash
cd MARS.Projects/MARS.Server && dotnet ef migrations add AddDanbooruScheduledPostTable --context AppDbContext
```

## Шаг 2: Изменения в сервисе `DanbooruAutoPostService.cs`

### 2.1 — Новые методы управления буфером

**`FillScheduleBufferAsync(Guid configId)`** — генерирует `DanbooruScheduledPost` записи для всех cron-слотов от `now` до `now + PlanningHorizonDays`. Пропускает уже существующие (уникальный индекс).

**`RescheduleBufferAsync(Guid configId)`** — при смене cron: отменяет все Pending записи → вызывает `FillScheduleBufferAsync`.

**`CleanupOldScheduledPostsAsync()`** — удаляет Posted/Cancelled записи старше 30 дней.

### 2.2 — Переработка `ProcessScheduledPostsAsync`

Новая структура вызовов:
1. `ProcessDueScheduledPostsAsync(now)` — обрабатывает записи из `DanbooruScheduledPost` где `ScheduledAtUtc <= now` и `Status == Pending`
2. `RefillAllTelegramBuffersAsync()` — для каждого включённого Telegram конфига с cron вызывает `FillScheduleBufferAsync`
3. `ProcessDiscordCronConfigsAsync(now)` — существующая логика cron для Discord (без изменений)
4. `CleanupOldScheduledPostsAsync()` — раз в час

### 2.3 — Изменения в CRUD методах

**`CreateAsync`**: после создания Telegram конфига с cron → `FillScheduleBufferAsync`

**`UpdateAsync`**: если изменился cron для Telegram → `RescheduleBufferAsync`. Если изменился `PlanningHorizonDays` → `FillScheduleBufferAsync`

**`SetEnabledAsync`**: при отключении Telegram → отменить Pending записи. При включении → `FillScheduleBufferAsync`

**`DeleteAsync`**: CASCADE удалит связанные `DanbooruScheduledPost` (настроено в FK)

**`GetAllAsync`**: заполнять `PendingPostsCount` и `NextScheduledAtUtc` из `DanbooruScheduledPost` через grouped query

### 2.4 — Удалить старую логику `ScheduledAtUtc` из `ProcessScheduledPostsAsync`

Убрать ветку `if (config.ScheduledAtUtc.HasValue && config.ScheduledAtUtc.Value <= now)` и `entity.ScheduledAtUtc = null; entity.IsEnabled = false;`

## Шаг 6: Edge Cases

| Сценарий | Решение |
|----------|---------|
| Смена cron на существующем конфиге | `RescheduleBufferAsync` — отменить Pending, заполнить заново |
| Смена PlanningHorizonDays | `FillScheduleBufferAsync` — новые записи до нового горизонта |
| Слишком частый cron (каждую минуту) | Cap в 1000 Pending записей на конфиг |
| Удаление конфига | CASCADE удалит все `DanbooruScheduledPost` |
| Отключение конфига | Отменить все Pending записи |
| Ошибка отправки | Пометить как `Failed`, логировать |
| Cleanup | Posted/Cancelled старше 30 дней удаляются раз в час |
