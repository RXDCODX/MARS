# Fix: Player State After Last Track Ends + Tests

## Problem

When the last track in the queue finishes, the player state becomes `Stopped`, but it should become `WaitingForTrack`. This also blocks new track requests because `AddTrackAsync` rejects requests when state is `Stopped`.

## Root Cause

In `MainPlayer.cs`, three places call `StopPlaybackAsync()` when the queue is empty, which sets state to `Stopped`:
1. `OnTrackEndedAsync` (line 664) — last track ends
2. `OnTrackErrorAsync` (line 733) — last track errors
3. `PlayNextFromQueueAsync` (line 427) — queue is empty

Additionally, `SoundRequestCommandsService.TryAutoPlayQueueItemAsync` only auto-plays when `wasPlayerStopped == true`, but `WaitingForTrack` is not `Stopped`, so new tracks won't auto-play.

## Fix

### 1. `MainPlayer.cs` — Replace `StopPlaybackAsync` with `SetCurrentQueueItemAsync(null)`

`SetCurrentQueueItemAsync(null)` already sets state to `WaitingForTrack` (line 288 of StateManager.cs), while `StopPlaybackAsync` sets state to `Stopped`.

**Changes:**

- **`OnTrackEndedAsync` (line 658-667)**: Replace `_stateManager.StopPlaybackAsync(notify: true)` with `_stateManager.SetCurrentQueueItemAsync(null, notify: true)`

- **`OnTrackErrorAsync` (line 728-734)**: Replace `_stateManager.StopPlaybackAsync(notify: true)` with `_stateManager.SetCurrentQueueItemAsync(null, notify: true)`

- **`PlayNextFromQueueAsync` (line 425-428)**: Replace `await StopAsync(_cancellationToken)` with `_stateManager.SetCurrentQueueItemAsync(null, notify: true)`

### 2. `SoundRequestCommandsService.cs` — Fix auto-play for `WaitingForTrack`

**`TryAutoPlayQueueItemAsync` (line 557-573)**: Change the condition from `wasPlayerStopped` to also include `WaitingForTrack`:

```csharp
private async Task TryAutoPlayQueueItemAsync(
    bool wasPlayerStopped,
    int queueCountBefore,
    QueueItem queueItem,
    CancellationToken cancellationToken
)
{
    // Auto-play when player was stopped/waiting AND queue was empty
    if ((wasPlayerStopped || stateManager.GetState().State == PlaybackState.WaitingForTrack)
        && queueCountBefore == 0 && playerController is MainPlayer mainPlayer)
    {
        await mainPlayer.PlayAsync(queueItem, cancellationToken);
        await NotifyQueueChangedAsync();
    }
    else
    {
        await NotifyQueueChangedAsync();
    }
}
```

Actually, simpler: just change the condition to check `queueCountBefore == 0` without requiring `wasPlayerStopped`, since if the queue was empty, we should auto-play regardless of state. But we need to be careful — if the player is `Playing` with a current track and queue is empty, we shouldn't auto-play. Let me reconsider.

Better approach: change `wasPlayerStopped` check to `wasPlayerStopped || wasPlayerWaiting`:

In `AddTrackAsync` (line 172-173), add:
```csharp
var wasPlayerWaiting = currentState.State == PlaybackState.WaitingForTrack;
```

And pass both flags to `TryAutoPlayQueueItemAsync`, which becomes:
```csharp
if ((wasPlayerStopped || wasPlayerWaiting) && queueCountBefore == 0 && ...)
```
