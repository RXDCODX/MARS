# Багфикс: SevenTvApiService — не установлен BaseAddress

## Проблема
Строка 66 `SevenTvApiService.cs`: `httpClientFactory.CreateClient(ClientName)` возвращает HttpClient без `BaseAddress`. Ветка с прокси (строка 56) корректно ставит `BaseAddress = new Uri(BaseUrl)`, а fallback-ветка — нет.

## Фикс
Файл: `Services/SevenTv/SevenTvApiService.cs`, строка 66.

Заменить:
```csharp
_httpClient = httpClientFactory.CreateClient(ClientName);
```
На:
```csharp
_httpClient = httpClientFactory.CreateClient(ClientName);
_httpClient.BaseAddress = new Uri(BaseUrl);
```

## Верификация
`dotnet build MARS.Server.csproj --configuration Release` + запуск сервера.

# План: Выделение сервиса SevenTV API с IHttpClientFactory и прокси из RootState

## Проблема

1. `SevenTvEmoteService` совмещает общение с 7TV API и фоновую логику кэширования
2. `SevenTVClient` из NuGet-пакета создаёт свой `HttpClient` внутри без возможности инжекции прокси
3. Нет настраиваемого прокси для HTTP-запросов к 7TV

## Решение

Создать `SevenTvApiService` в `Services/SevenTv/`, который:
- Использует `IHttpClientFactory` для создания `HttpClient`
- Читает прокси из `RootState` (новый ключ `SevenTvProxyUrl`)
- Делает прямые HTTP-запросы к 7TV REST API (`https://7tv.io/v3/...`)
- Десериализует ответы в типы из пакета `SevenTV-lib` (`SevenTV.Types.Rest`)
- Пакет `SevenTV-lib` остаётся **только** для типов, `SevenTVClient` больше не используется

---

## Файлы для создания

### 1. `Services/SevenTv/ISevenTvApiService.cs`

```csharp
using SevenTV.Types.Rest;

namespace MARS.Server.Services.SevenTv;

public interface ISevenTvApiService
{
    Task<User?> GetUserAsync(string userId);
    Task<EmoteSet?> GetEmoteSetAsync(string emoteSetId);
}
```

### 2. `Services/SevenTv/SevenTvApiService.cs`

Синглтон. Конструктор принимает `IHttpClientFactory`, `IDbContextFactory<AppDbContext>`, `ILogger`.

**Инициализация:**
- При первом вызове читает `SevenTvProxyUrl` из `RootState` через `IDbContextFactory`
- Создаёт `HttpClient` через `httpClientFactory.CreateClient("SevenTv")` 
- Если прокси задан — оборачивает в `HttpClientHandler` с `WebProxy`

**Методы:**
- `GetUserAsync(userId)` → `GET https://7tv.io/v3/users/{userId}` → десериализация в `User?`
- `GetEmoteSetAsync(emoteSetId)` → `GET https://7tv.io/v3/emote-sets/{emoteSetId}` → десериализация в `EmoteSet?`

Использует `System.Net.Http.Json` для десериализации.

## Файлы для изменения

### 3. `ApplicationState/RootState.cs`

Добавить в `RootStateKeys`:
```csharp
public const string SevenTvProxyUrl = "SevenTvProxyUrl";
```

### 4. `DataBaseContext/AppDbContext.cs` (~строка 291)

Добавить seed в `HasData`:
```csharp
new RootState
{
    Name = RootStateKeys.SevenTvProxyUrl,
    Value = string.Empty,
    Description = "Прокси для 7TV API: http://user:pass@host:port или socks5://user:pass@host:port",
    TypeDescription = "string",
},
```

### 5. `StartupExstensions.cs` (метод `AddSyntheziaServices`, ~строка 598)

Добавить перед регистрацией `SevenTvEmoteService`:
```csharp
services.AddSingleton<ISevenTvApiService, SevenTvApiService>();
```

### 6. `Services/Twitch/Synthesizer/SevenTvEmoteService.cs`

- Убрать `using SevenTV;`
- Добавить `using MARS.Server.Services.SevenTv;`
- Конструктор: заменить `SevenTVClient? sevenTvClient = null` → `ISevenTvApiService sevenTvApiService`
- Убрать поле `internal readonly SevenTVClient _sevenTvClient`
- Добавить поле `private readonly ISevenTvApiService _sevenTvApiService`
- В `RefreshEmotesAsync` заменить:
  - `_sevenTvClient.rest.GetUser(...)` → `_sevenTvApiService.GetUserAsync(...)`
  - `_sevenTvClient.rest.GetEmoteSet(...)` → `_sevenTvApiService.GetEmoteSetAsync(...)`

### 7. `MARS.Server.csproj` (если нужно)

Пакет `SevenTV-lib` остаётся — он нужен для типов `User`, `EmoteSet` и т.д.
