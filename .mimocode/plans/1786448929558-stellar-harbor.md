# Refined DanbooruAutoPost: Cron + Time Range Batch, Reschedule

## Context

The user needs to:
1. Specify a **cron expression + end date** (e.g., `*/2 * * * *` for the next month). The system generates all deferred posts for the entire period.
2. **Batch download** images from Danbooru to fill those slots (download once, reuse for reschedule).
3. **Reschedule** existing batch: change the cron and regenerate `ScheduledAtUtc` for all future posts, keeping the same images.

## Entity Changes

### `DanbooruAutoPostConfig` — add `BatchId`

```csharp
public Guid? BatchId { get; set; }  // groups deferred posts from one batch
```

All deferred posts from the same batch share a `BatchId`. Used for:
- Rescheduling all posts in a batch
- Deleting an entire batch
- UI grouping

### New entity: `DanbooruBatchImage` (downloaded image cache)

**File**: `Services/DanbooruAutoPost/Entities/DanbooruBatchImage.cs` (new)

```csharp
public class DanbooruBatchImage
{
    [Key]
    public Guid Id { get; set; } = Guid.NewGuid();
```

Purpose: Cache downloaded image metadata per batch. When rescheduling, we reuse these images instead of re-downloading.

## Service Changes (`DanbooruAutoPostService.cs`)

### `BatchCreateAsync` — rewrite

New flow:
1. Validate: cron expression, end date > now, target platform/channel
2. Parse cron → compute interval between occurrences
3. Generate all `ScheduledAtUtc` slots from now to `endAtUtc`
4. Call `danbooruService.GetRandomPostAsync(tags, slotCount)` to fetch N images at once
5. Check deduplication, filter out already-posted images
6. If not enough unique images, use what's available (partial batch)
7. Save images to `DanbooruBatchImages` table (for reschedule reuse)
8. Create `DanbooruAutoPostConfig` entries with `BatchId`, `ScheduledAtUtc`, `Tags` (from the image's tags), `IsEnabled = true`, `CronExpression = ""`
9. Return created configs

### New method: `RescheduleBatchAsync`

Flow:
1. Validate batch exists and all posts are still deferred (not yet posted)
2. Parse new cron expression
3. Load all configs with the given `BatchId` where `ScheduledAtUtc > now`
4. Recompute `ScheduledAtUtc` for each based on new cron, preserving order
5. Update configs in DB
6. Return updated configs

### New method: `DeleteBatchAsync`

Flow:
1. Load all configs with the given `BatchId`
2. Delete them all
3. Delete associated `DanbooruBatchImages` for that batch

### `PostImageAsync` — no change needed

Already handles deferred posts by checking `ScheduledAtUtc`.
