# Plan: Add tests verifying WaifuRoll returns a waifu present in WaifuPrizes

## Context

`WaifuRollService.RollTheWaifu()` picks a random waifu from the top-10 by `LastOrder` in the `Waifus` table. `WaifuPrizesService.GetWaifuPrizesAsync()` returns ALL waifus from the same table as `PrizeType` DTOs. Both services share the same DB, so any waifu returned by RollTheWaifu **must** appear in WaifuPrizes. We need tests proving this invariant.

## Approach

Add integration-style tests to the **existing** `WaifuRollServiceTests.cs` file using the already-established test patterns (InMemory DB, `SeedWaifuAsync`, `CreateService`/`CreateServiceWithDeps`).

### New tests (3 total)

All tests seed waifus into the InMemory DB, call `RollTheWaifu` with `forcePass: true` (to bypass cooldown/channel-owner checks), then call `GetWaifuPrizesAsync` via `WaifuPrizesService` on the **same DB factory**, and assert the rolled waifu's `ShikiId` exists in the prizes collection.

1. **`RollTheWaifu_WhenWaifuReturned_IsPresentInPrizes`** — Seeds 3 non-privated waifus, rolls one, verifies its `ShikiId` is in `GetWaifuPrizesAsync()` results.

2. **`RollTheWaifu_WithMultipleRolls_EachResultPresentInPrizes`** — Seeds 5 waifus, rolls 5 times (each with a different TwitchId or via `forcePass`), verifies every rolled waifu appears in prizes.

3. **`RollTheWaifu_WhenSingleWaifuExists_ReturnsThatWaifuWhichIsInPrizes`** — Seeds exactly 1 waifu, rolls, verifies the single waifu is returned and matches the single prize.

### Helper needed

A small helper `GetPrizesAsync(dbFactory)` that creates a `WaifuPrizesService` and calls `GetWaifuPrizesAsync()` — reuses the existing `TestAppDbContextFactory`, `CreateShikimoriOptions` pattern, and `CreateWaifuRollEnsurenceService` from `WaifuPrizesServiceTests`.

Since both test classes share `TestAppDbContextFactory`, the new tests will define their own local version (same pattern as existing code — both files already duplicate this class).
