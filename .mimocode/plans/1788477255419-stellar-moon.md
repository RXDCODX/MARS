# Plan: Run MARS.AutoTests Locally in Docker

## Goal

Containerize the MARS.AutoTests Playwright test runner so that the full integration test suite (AppAvailabilityTests, ObsComponentsTests, PyroAlertsIntegrationTests, ConsoleErrorTests) can run locally via a single `docker compose` command — no host-side .NET SDK, Node, or Playwright install required.

## Current State

| Component | Status |
|---|---|
| `docker-compose.autotests.yml` | Runs MARS.Server (Staging, port 9725) + PostgreSQL + DB restore. Used in CI. |
| `MARS.Server/Dockerfile` | Multi-stage build (SDK → publish → aspnet runtime). Works. |
| `AutoTestsFixture.cs` | Supports `MARS_SERVER_URL` env var — connects to an external server instead of launching one locally. |
| `PyroAlertsIntegrationTests.CopyTestFilesToServer()` | Copies 3 files from `MARS.AutoTests/Files/` → `MARS.Server/wwwroot/Alerts/` via local filesystem. **Breaks in Docker** (separate containers). |
| `.dockerignore` | Excludes `MARS.Projects/MARS.AutoTests/` — must be removed for the test runner build context. |
| Test runner (Playwright + dotnet test) | Runs on HOST only. Not containerized. |

### Shared Volume Strategy (PyroAlerts fix)

The key challenge: `CopyTestFilesToServer()` writes files to `{repoRoot}/MARS.Projects/MARS.Server/wwwroot/Alerts/` on the local filesystem. In Docker, the server and test runner are separate containers.

**Solution**: A named Docker volume `alert-files` is mounted at `/app/wwwroot/Alerts` in both containers. The test runner copies files into this volume; the server reads them via its static file middleware.

However, `CopyTestFilesToServer()` uses `AppSettingsHelper.FindRepoRoot()` to compute paths. Inside the test runner container, the repo root will be `/src` and the server's wwwroot will NOT be at `/src/MARS.Projects/MARS.Server/wwwroot/Alerts/` — it will be at `/app/wwwroot/Alerts/` (the volume mount).

**Approach**: We need to make `CopyTestFilesToServer()` Docker-aware. Two options:

1. **Symlink approach** (preferred — no code change): In the test runner Dockerfile, create a symlink from `/src/MARS.Projects/MARS.Server/wwwroot/Alerts` → `/app/wwwroot/Alerts` (the volume mount). This way the existing code path works unchanged.

2. **Env var approach**: Add an env var `ALERTS_DIR_OVERRIDE` that `CopyTestFilesToServer()` checks. More explicit but requires code change.

**Decision**: Use the symlink approach. The test runner Dockerfile will create the symlink before running tests.

## Files to Create/Modify

### 1. NEW: `MARS.Projects/MARS.AutoTests/Dockerfile`

Single-stage Dockerfile (SDK image needed for `dotnet test` anyway).

```dockerfile
FROM mcr.microsoft.com/dotnet/sdk:10.0

ENV HUSKY=0

# Install system deps: Playwright/Chromium + GStreamer (media playback) + ffmpeg
RUN apt-get update && \
    apt-get install -y --no-install-recommends \
        libnss3 libatk1.0-0 libatk-bridge2.0-0 libcups2 libdrm2 \
        libxkbcommon0 libxcomposite1 libxdamage1 libxfixes3 libxrandr2 \
        libgbm1 libpango-1.0-0 libcairo2 libasound2 \
        libwayland-client0 libwayland-egl1 \
        fonts-liberation fonts-noto-color-emoji \
        libgstreamer1.0-0 gstreamer1.0-plugins-base \
        gstreamer1.0-plugins-good gstreamer1.0-plugins-bad gstreamer1.0-libav \
        ffmpeg && \
    rm -rf /var/lib/apt/lists/*

WORKDIR /src

# Copy solution-level files for NuGet restore caching
COPY Directory.Packages.props .
COPY MARS.Projects/MARS.AutoTests/MARS.AutoTests.csproj MARS.Projects/MARS.AutoTests/
COPY MARS.Projects/MARS.Server/MARS.Server.csproj MARS.Projects/MARS.Server/
COPY MARS.Projects/MARS.Shared/MARS.Shared.csproj MARS.Projects/MARS.Shared/
COPY MARS.Projects/MARS.Server/external/ MARS.Projects/MARS.Server/external/

RUN dotnet restore MARS.Projects/MARS.AutoTests/MARS.AutoTests.csproj \
    -p:UseLocalYoutubeReExplode=false \
    -p:RunTestsOnPublish=false \
    -p:SkipHusky=true

# Copy full source (including AutoTests/Files/ with test media + MARS.sln)
COPY . .

# Build and install Playwright Chromium
RUN dotnet build MARS.Projects/MARS.AutoTests/MARS.AutoTests.csproj -c Release && \
    pwsh MARS.Projects/MARS.AutoTests/bin/Release/net10.0/playwright.ps1 install chromium

# Create symlink for shared alert volume
# Test code writes to {repoRoot}/MARS.Projects/MARS.Server/wwwroot/Alerts/
# Symlink redirects to /app/wwwroot/Alerts (the shared Docker volume mount)
RUN mkdir -p /app/wwwroot/Alerts /src/MARS.Projects/MARS.Server/wwwroot && \
    ln -sf /app/wwwroot/Alerts /src/MARS.Projects/MARS.Server/wwwroot/Alerts

ENV MARS_SERVER_URL=http://mars-server:9725

ENTRYPOINT ["dotnet", "test", \
    "MARS.Projects/MARS.AutoTests/MARS.AutoTests.csproj", \
    "--configuration", "Release", \
    "--logger", "trx", \
    "--results-directory", "/src/TestResults"]
```

**Key design decisions**:
- Single-stage build — `sdk:10.0` is needed for `dotnet test` anyway, no benefit from multi-stage
- Installs Playwright Chromium via the `playwright.ps1` script from the built NuGet package (official .NET method)
- GStreamer packages included for PyroAlerts video/audio tests
- Creates symlink for the alerts shared volume (no C# code changes needed)
- Entrypoint is `dotnet test` — can be overridden for selective test runs
- `MARS_SERVER_URL` defaults to `http://mars-server:9725` (Docker Compose service name)
- Copies `external/` directory for transitive project references (YoutubeExplode, DSharpPlus)

### 2. NEW: `docker-compose.autotests-local.yml`

Extends the existing `docker-compose.autotests.yml` pattern with the autotests service.

```yaml
# docker-compose.autotests-local.yml
# Run MARS.AutoTests entirely in Docker (no host-side SDK/Playwright needed).
#
# Usage:
#   docker compose -f docker-compose.autotests-local.yml up --build --abort-on-container-exit
#   docker compose -f docker-compose.autotests-local.yml down -v

services:
  # ── Infrastructure (reused from existing pattern) ──

  postgres:
    image: postgres:16-alpine
    environment:
      POSTGRES_USER: postgres
      POSTGRES_PASSWORD: postgres
      POSTGRES_DB: prod
    ports:
      - "5433:5432"
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U postgres"]
      interval: 5s
      timeout: 3s
      retries: 10
    volumes:
      - postgres-data:/var/lib/postgresql/data

  db-restore:
    image: postgres:16-alpine
    depends_on:
      postgres:
        condition: service_healthy
    volumes:
      - ./Sql_backup:/backups:ro
    environment:
      PGPASSWORD: postgres
    entrypoint: >
      sh -c '
        echo "=== Looking for latest SQL backup ==="
        LATEST=$$(ls -d /backups/VS-snapshot_* 2>/dev/null | sort -r | head -1)
        if [ -z "$$LATEST" ]; then
          echo "ERROR: No VS-snapshot_* directories found in /backups"
          exit 1
        fi
        echo "=== Latest backup dir: $$LATEST ==="
        SQL_FILE=$$(find "$$LATEST" -maxdepth 1 -name "*.sql" | head -1)
        if [ -z "$$SQL_FILE" ]; then
          echo "ERROR: No .sql file found in $$LATEST"
          exit 1
        fi
        echo "=== Restoring: $$SQL_FILE ==="
        PGPASSWORD=postgres psql -h postgres -U postgres -d postgres -f "$$SQL_FILE" --set ON_ERROR_STOP=off
        echo "=== Database restored ==="
      '

  # ── Application ──

  mars-server:
    build:
      context: .
      dockerfile: MARS.Projects/MARS.Server/Dockerfile
      args:
        SKIP_BUILD_CLIENT: "true"
    image: localhost/mars-server:autotests
    depends_on:
      db-restore:
        condition: service_completed_successfully
    ports:
      - "9725:9725"
    environment:
      ASPNETCORE_ENVIRONMENT: Staging
      ASPNETCORE_URLS: "http://+:9725"
    volumes:
      - alert-files:/app/wwwroot/Alerts

  # ── Test Runner ──

  autotests:
    build:
      context: .
      dockerfile: MARS.Projects/MARS.AutoTests/Dockerfile
    depends_on:
      mars-server:
        condition: service_started
    environment:
      MARS_SERVER_URL: "http://mars-server:9725"
      HEADED: "false"
    volumes:
      - alert-files:/app/wwwroot/Alerts
      - ./TestResults:/src/TestResults
    # Override entrypoint to run specific tests:
    #   docker compose ... run autotests dotnet test ... --filter "FullyQualifiedName~PyroAlerts"

volumes:
  postgres-data:
  alert-files:
```

**Key design decisions**:
- `alert-files` named volume is mounted at `/app/wwwroot/Alerts` in BOTH `mars-server` and `autotests`
- `mars-server` uses `service_started` (not `service_healthy`) — the `AutoTestsFixture` already polls for 30s via `MARS_SERVER_URL` flow
- `TestResults` are bind-mounted to host for easy inspection
- `postgres-data` named volume persists DB data across compose restarts (avoids re-restore)
- `--abort-on-container-exit` stops everything when tests finish

### 3. NEW: `run-autotests-local.ps1`

PowerShell convenience script.

```powershell
<#
.SYNOPSIS
    Run MARS.AutoTests locally in Docker containers.

.DESCRIPTION
    Builds and runs the full AutoTests suite (Playwright + xUnit) against
    a containerized MARS.Server with PostgreSQL.

.PARAMETER Filter
    Optional xUnit filter expression. Examples:
      "FullyQualifiedName~PyroAlerts"
      "FullyQualifiedName~AppAvailability"
      "FullyQualifiedName~ObsComponents"
      "ClassName=ConsoleErrorTests"

.PARAMETER NoBuild
    Skip Docker image rebuild (use cached images).

.PARAMETER Clean
    Remove all containers, volumes, and images before running.

.EXAMPLE
    .\run-autotests-local.ps1
    .\run-autotests-local.ps1 -Filter "FullyQualifiedName~PyroAlerts"
    .\run-autotests-local.ps1 -NoBuild
    .\run-autotests-local.ps1 -Clean
#>

param(
    [string]$Filter,
    [switch]$NoBuild,
    [switch]$Clean
)

$ErrorActionPreference = "Stop"
$composeFile = "docker-compose.autotests-local.yml"

# ── Clean ──
if ($Clean) {
    Write-Host "🧹 Cleaning up Docker resources..." -ForegroundColor Yellow
    docker compose -f $composeFile down -v --rmi local 2>$null
    Write-Host "✅ Clean complete." -ForegroundColor Green
    if (-not $Filter -and $NoBuild) { exit 0 }
}

# ── Build ──
if (-not $NoBuild) {
    Write-Host "🔨 Building Docker images..." -ForegroundColor Cyan
    docker compose -f $composeFile build
    if ($LASTEXITCODE -ne 0) {
        Write-Host "❌ Build failed!" -ForegroundColor Red
        exit 1
    }
}

# ── Run ──
if ($Filter) {
    Write-Host "🧪 Running filtered tests: $Filter" -ForegroundColor Cyan
    docker compose -f $composeFile run --rm autotests `
        dotnet test MARS.Projects/MARS.AutoTests/MARS.AutoTests.csproj `
        --configuration Release `
        --logger trx `
        --results-directory /src/TestResults `
        --filter $Filter
} else {
    Write-Host "🧪 Running all AutoTests..." -ForegroundColor Cyan
    docker compose -f $composeFile up --abort-on-container-exit --exit-code-from autotests
}

$testExitCode = $LASTEXITCODE

# ── Report ──
if ($testExitCode -eq 0) {
    Write-Host "✅ All tests passed!" -ForegroundColor Green
} else {
    Write-Host "❌ Tests failed (exit code: $testExitCode)" -ForegroundColor Red
}

# ── Cleanup containers (keep volumes for caching) ──
Write-Host "🧹 Stopping containers..." -ForegroundColor Yellow
docker compose -f $composeFile down

# ── Show results location ──
$resultsPath = Join-Path $PSScriptRoot "TestResults"
if (Test-Path $resultsPath) {
    Write-Host "📊 Test results: $resultsPath" -ForegroundColor Cyan
    $trxFiles = Get-ChildItem -Path $resultsPath -Filter "*.trx" -Recurse
    if ($trxFiles) {
        Write-Host "   TRX files:" -ForegroundColor Gray
        $trxFiles | ForEach-Object { Write-Host "   - $($_.FullName)" -ForegroundColor Gray }
    }
}

exit $testExitCode
```

### 4. MODIFY: `.dockerignore`

Remove the `MARS.Projects/MARS.AutoTests/` exclusion so the test runner Dockerfile can access the AutoTests source and Files/ directory.

**Current** (line 53):
```
MARS.Projects/MARS.AutoTests/
```

**Change**: Remove this line entirely.

Also remove the `run-autotests-local.ps1` exclusion (line 56) since we now have this file:
```
run-autotests-local.ps1
```

**Rationale**: The `.dockerignore` applies to ALL Docker builds in this context. The existing MARS.Server Dockerfile doesn't need AutoTests, but it also doesn't hurt to include it (it's small). The alternative — using separate `.dockerignore` files per Dockerfile — is not supported by Docker BuildKit with a shared context. The simplest fix is to remove the exclusion.

**Risk**: Slightly larger build context for MARS.Server builds. The AutoTests project is ~500KB (source + 3 test media files), so this is negligible.

### Step 2: Create `MARS.Projects/MARS.AutoTests/Dockerfile`

1. **Single-stage build**: Uses `sdk:10.0` directly since `dotnet test` requires the SDK. No benefit from multi-stage.

2. **Playwright browser installation**: After `dotnet build`, the `playwright.ps1` script is at `bin/Release/net10.0/playwright.ps1`. Run `pwsh playwright.ps1 install chromium` — this is the officially supported method for .NET Playwright.

The symlink redirects writes to the shared volume.

4. **GStreamer packages**: PyroAlerts tests play video/audio. Chromium needs GStreamer for media playback in headless mode.

5. **Entrypoint**: `dotnet test` with TRX logger. Results go to `/src/TestResults` which is bind-mounted to host.

### Step 3: Create `docker-compose.autotests-local.yml`

Full content as specified above. Key implementation notes:

1. **No healthcheck on mars-server**: The `AutoTestsFixture` already polls `MARS_SERVER_URL` for up to 30 seconds. `depends_on: service_started` ensures the container is running; the fixture handles readiness.

2. **Shared volume `alert-files`**: Named volume mounted at `/app/wwwroot/Alerts` in both containers. This is the Docker solution to the cross-container file copy problem.

3. **TestResults bind mount**: `./TestResults:/src/TestResults` allows inspecting TRX files on the host after tests complete.

4. **postgres-data named volume**: Persists the restored database across runs. First run restores from SQL backup; subsequent runs skip the restore (db-restore service still runs but the data is already there). To force a fresh restore: `docker compose ... down -v` to remove volumes.

## Risks & Mitigations

| Risk | Impact | Mitigation |
|---|---|---|
| Playwright browser install fails in Docker | Tests can't run | Fallback: use `mcr.microsoft.com/playwright/dotnet:v1.62.0-noble` as base image (ships with browsers pre-installed). Check [Playwright Docker docs](https://playwright.dev/docs/docker). |
| GStreamer missing → video/audio tests fail | PyroAlerts media tests fail | GStreamer packages are included in Dockerfile. If specific codecs missing, add `gstreamer1.0-plugins-ugly`. |
| Server not ready when tests start | Tests fail with connection errors | `AutoTestsFixture` polls `MARS_SERVER_URL` for up to 30s. `depends_on: service_started` ensures container is running. Combined wait is sufficient. |
| `alert-files` volume has stale data from previous run | False positive/negative test results | `RemoveCopiedTestFiles()` in PyroAlerts cleans up after each test. Volume is fresh on first run. |
| `.dockerignore` change bloats MARS.Server build context | Slower server builds | AutoTests dir is ~500KB. Negligible impact. |
| `FindRepoRoot()` fails in container | Tests crash | In container, `MARS.sln` is at `/src/MARS.sln`. `FindRepoRoot()` walks up from CWD which is `/src`. Should work. Verify in smoke test. |

## Alternative Approaches Considered

### A. Use `mcr.microsoft.com/playwright/dotnet` base image
- **Pro**: Pre-installed browsers, no manual Playwright install
- **Con**: Only available for specific .NET versions; may not match .NET 10 SDK
- **Decision**: Try SDK:10.0 + manual install first. Fall back to Playwright image if browser install fails.

### B. Multi-stage build (build + runtime)
- **Pro**: Smaller final image (aspnet instead of sdk)
- **Con**: `dotnet test` needs the SDK; published DLLs don't work well with xUnit test discovery. Would need to copy full source to runtime stage anyway, negating the size benefit.
- **Decision**: Rejected. Single-stage with SDK is simpler and more reliable.

### C. Mount host repo as volume (no COPY)
- **Pro**: No Dockerfile build step, instant code changes
- **Con**: Requires host .NET SDK inside container anyway; NuGet restore on every run; platform-specific issues (Windows paths in Linux container)
- **Decision**: Rejected. Full COPY build is more reproducible.
