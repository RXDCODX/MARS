## Задача 2: DateTime Kind bug

**Ошибка:** `Cronos.CronExpression.GetNextOccurrence()` требует `DateTime.Kind == Utc`, но EF Core возвращает `Kind = Unspecified`.

**Причина:** В entity `DanbooruAutoPostConfig` и `NSFWBooruAutoPostConfig` дефолты `CreatedAtUtc = DateTime.Now` / `UpdatedAtUtc = DateTime.Now` — это local time, а не UTC. Плюс в CRUD методах используется `DateTime.Now`.

**Файлы для исправления:**

### Fix 1 — Защита при чтении (ProcessScheduledPostsAsync)

В `DanbooruAutoPostService.cs` ~line 64 и `NSFWBooruAutoPostService.cs` ~line 65:

```csharp
// Было:
var nextOccurrence = config.LastExecutedAtUtc.HasValue
    ? cron.GetNextOccurrence(config.LastExecutedAtUtc.Value)
    : cron.GetNextOccurrence(now.AddMinutes(-1));

// Стало:
var lastExecuted = config.LastExecutedAtUtc.HasValue
    ? DateTime.SpecifyKind(config.LastExecutedAtUtc.Value, DateTimeKind.Utc)
    : (DateTime?)null;

var nextOccurrence = lastExecuted.HasValue
    ? cron.GetNextOccurrence(lastExecuted.Value)
    : cron.GetNextOccurrence(now.AddMinutes(-1));
```

### Fix 2 — Корневая причина: DateTime.Now → DateTime.UtcNow

Все 4 файла:

| Файл | Строки | Изменение |
|------|--------|-----------|
| `DanbooruAutoPostConfig.cs` | 21, 23 | `DateTime.Now` → `DateTime.UtcNow` |
| `NSFWBooruAutoPostConfig.cs` | 21, 23 | `DateTime.Now` → `DateTime.UtcNow` |
| `DanbooruAutoPostService.cs` | 309, 404, 510 | `DateTime.Now` → `DateTime.UtcNow` |
| `NSFWBooruAutoPostService.cs` | 310, 405, 521 | `DateTime.Now` → `DateTime.UtcNow` |
