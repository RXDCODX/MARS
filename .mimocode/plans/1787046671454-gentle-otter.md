# Plan: Обработка ошибок DanbooruTelegramPoster и WTelegramClientService

## Задача 1: DanbooruTelegramPoster — обработка PHOTO_SAVE_FILE_INVALID + PHOTO_INVALID_DIMENSIONS

### Проблема
Telegram API возвращает `PHOTO_SAVE_FILE_INVALID` и `PHOTO_INVALID_DIMENSIONS` когда изображение не проходит валидацию. Ограничения Telegram (Bot API `sendPhoto`):
- **Макс размер**: 10 MB
- **Width + Height**: не более 10000 суммарно
- **Aspect ratio**: не более 20:1 (width/height)

### Решение
1. **Превентивная валидация** — перед первой отправкой проверять размеры через ImageSharp, конвертировать если нарушены лимиты
2. **Catch-обработка** — если сервер всё равно отклонил, повторить с конвертированным изображением, fallback на document

### Файл
`MARS.Projects/MARS.Server/Services/DanbooruAutoPost/DanbooruTelegramPoster.cs`

### Изменения
1. Добавить `using SixLabors.ImageSharp;`, `using SixLabors.ImageSharp.Formats.Jpeg;`, `using SixLabors.ImageSharp.Processing;`
2. Добавить приватный метод `EnsureTelegramPhotoCompatibleAsync(byte[] fileBytes, string fileName)`:
   - `Image.LoadAsync` → проверка constraints (size ≤ 10MB, w+h ≤ 10000, ratio ≤ 20:1)
   - Если нарушены: ресайз (ResizeMode.Max, maxDimension=5000), JPEG quality=85
   - Возвращает `(byte[] bytes, string fileName, bool converted)`
3. Вызвать `EnsureTelegramPhotoCompatibleAsync` **до** `Messages_SendMedia` (превентивно)
4. Расширить catch с `PHOTO_INVALID_DIMENSIONS` → catch для обоих (`PHOTO_INVALID_DIMENSIONS` + `PHOTO_SAVE_FILE_INVALID`)
5. В catch-блоке: retry с конвертированным изображением → fallback на document
6. Single-return pattern

## Задача 2: WTelegramClientService — обработка FLOOD_WAIT

### Проблема
При `LoginUserIfNeeded()` Telegram возвращает `420 FLOOD_WAIT_16`. Нужно подождать 16 сек и повторить. См. https://github.com/wiz0u/WTelegramClient/issues/334#issuecomment-3314916448

### Решение
Retry-обёртка с FLOOD_WAIT handling в `PerformAuthorizationAsync`.

### Файл
`MARS.Projects/MARS.Server/Services/Telegram/WTelegram/WTelegramClientService.cs`

### Изменения
1. Приватный метод `InvokeWithFloodWaitRetryAsync(Func<Task> action)`:
   - Catch `WTelegram.RpcException` с `Message` содержащим `FLOOD_WAIT_`
   - Парсинг секунд из `FLOOD_WAIT_N`
   - `await Task.Delay((seconds + 1) * 1000)`
   - Retry, макс 3 попытки
2. Обернуть `client.LoginUserIfNeeded()` в `PerformAuthorizationAsync` через `InvokeWithFloodWaitRetryAsync`
3. Single-return pattern
