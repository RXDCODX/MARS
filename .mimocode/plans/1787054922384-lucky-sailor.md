# Plan: rollmiku команда — убрать мутацию коллекции и ролла

## Проблема
Команда `rollmiku` через `RecordRollAsync()` записывает ролл в коллекцию пользователя и через `RollTheMiku()` мутирует `OrderCount`/`LastOrder` модуля. Нужно чтобы команда была полностью read-only.

## Решение

### 1. Добавить read-only метод в `MikuRollService`
**Файл:** `MARS.Server/Services/Twitch/Rewards/4_MikuRoll/MikuRollService.cs`

Добавить метод `GetNextMikuModuleAsync()` — возвращает модуль с наименьшим `LastOrder` **без** инкремента `OrderCount` и обновления `LastOrder`:

```csharp
public async Task<MikuModule?> GetNextMikuModuleAsync(CancellationToken cancellationToken = default)
{
    MikuModule? result = null;

    try
    {
        await using var dbContext = await factory.CreateDbContextAsync();
        result = await dbContext.Miku
            .AsNoTracking()
            .OrderBy(e => e.LastOrder)
            .FirstOrDefaultAsync(cancellationToken);
    }
    catch
    {
    }

    return result;
}
```

### 2. Переписать `RollMikuCommand.ExecuteAsync`
**Файл:** `MARS.Server/Services/CommandExecutor/Commands/rollmiku_command.cs`

Замены:
- `mikuRollService.RollTheMiku()` → `mikuRollService.GetNextMikuModuleAsync(cancellationToken)`
- `collectionService.RecordRollAsync(...)` → `collectionService.GetUserCollectionStatsAsync(twitchUser.TwitchId)` (read-only, возвращает `(collected, total)`)
- Убрать `MikuCollectionService` из DI-конструктора, если он больше нигде не используется в команде — **нет**, `GetUserCollectionStatsAsync` тоже находится в `MikuCollectionService`, поэтому зависимость остаётся.

Итоговый ExecuteAsync (ключевой блок):
```csharp
var module = await mikuRollService.GetNextMikuModuleAsync(cancellationToken);

if (module is not null)
{
    var (collectedCount, totalCount) = await collectionService
        .GetUserCollectionStatsAsync(twitchUser.TwitchId);

    await alertsHub.Clients.All.MikuRoll(
        module,
        twitchUser,
        collectedCount,
        totalCount
    );
}
```
