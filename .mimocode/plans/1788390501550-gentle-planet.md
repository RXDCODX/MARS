# Separate Proxy Configuration for Bot API and WTelegram

## Problem
1. Both clients share the same `WTelegramProxyUrl` key — can't configure independently
2. Proxy type auto-detection from URI scheme fails in some cases (e.g. "non-connected sockets" error)
3. Need ability to force proxy type (socks5/http) per client

## Solution
Add separate proxy URLs and explicit proxy type overrides for each client.

---

## New `RootStateKeys` (`ApplicationState/RootState.cs`)

| Key | Purpose | Values |
|-----|---------|--------|
| `TelegramBotProxyUrl` | Proxy URL for Bot API | `socks5://...`, `http://...`, `t.me/socks?...` |
| `TelegramBotProxyType` | Force proxy type for Bot API | `socks5`, `http`, `auto` (default) |
| `WTelegramProxyType` | Force proxy type for WTelegram | `socks5`, `http`, `auto` (default) |

Existing keys `WTelegramProxyUrl` / `WTelegramMtProxyUrl` remain for WTelegram.

---

## Files to Modify

### 1. `ApplicationState/RootState.cs`
Add 3 new constants to `RootStateKeys`.

### 2. `Services/Telegram/TelegramProxyHelper.cs`

**Update `ReadBotProxyUri`**: read from `TelegramBotProxyUrl` first, fallback to `WTelegramProxyUrl`.

**Add `ReadWTelegramProxyType` / `ReadTelegramBotProxyType`**: read type override from RootState.

**Add `ResolveProxyUri(string proxyValue, string? forceType)`**: 
- If `forceType == "socks5"` → parse as `socks5://` (strip scheme, rebuild)
- If `forceType == "http"` → parse as `http://` (strip scheme, rebuild)
- If `forceType == "auto"` or null → current auto-detection logic

**Update `ConnectThroughHttpProxyAsync`**: ensure credentials are passed correctly.

### 3. `Services/Telegram/WTelegram/WTelegramClientService.cs`

**Update `ApplyProxyConfigurationAsync`**:
- Read `WTelegramProxyType` from RootState
- Pass to `TelegramProxyHelper.ResolveProxyUri(proxyValue, forceType)`
- Log the forced type when set

### 4. `StartupExstensions.cs`

**Update `ConfigurePrimaryHttpMessageHandler`**:
- Read `TelegramBotProxyType` from RootState
- Pass to `TelegramProxyHelper.ResolveProxyUri(proxyValue, forceType)`

## Proxy Type Resolution Logic

```
ResolveProxyUri(proxyValue, forceType):
  if forceType == "socks5":
    // Strip any scheme, rebuild as socks5://
    return socks5://user:pass@host:port
  if forceType == "http":
    // Strip any scheme, rebuild as http://
    return http://user:pass@host:port
  if forceType == "auto" or null:
    // Current logic: detect from URI scheme
    return auto-detected Uri
```

---

## Error Handling

| Scenario | Behavior |
|---|---|
| `TelegramBotProxyUrl` not set | Fallback to `WTelegramProxyUrl` |
| `ProxyType` not set or "auto" | Auto-detect from URI scheme |
| `ProxyType` = "socks5" but URL is `http://` | Force SOCKS5 connection |
| `ProxyType` = "http" but URL is `socks5://` | Force HTTP CONNECT |
| MTProxy URL for Bot API | Skip with warning |

## Verification

1. Set `WTelegramProxyUrl` = `http://user:pass@host:port` in RootState
2. Set `WTelegramProxyType` = `http` to force HTTP for WTelegram
3. Set `TelegramBotProxyUrl` = same or different proxy
4. Set `TelegramBotProxyType` = `http` to force HTTP for Bot API
5. Verify both clients connect through proxy without "non-connected sockets" error
