# Plan: Startup catch-up for TelegramDiscordBridgeService

## Problem

The service only processes **live** Telegram updates via `_client.OnUpdates`. If the service was down when messages were posted to a Telegram channel, those messages are never forwarded to Discord. The `TelegramDiscordChannelStates.LastProcessedMessageId` is already tracked but never used for catch-up on startup.

## Goal

On startup, after the Telegram client is initialized, fetch **ALL** messages since `LastProcessedMessageId` from each bound Telegram channel and forward them to Discord — with a 1-minute cooldown between sends to avoid rate limits.

## Implementation

### 1. Add `GetInputPeerChannelAsync` helper

```csharp
private async Task<InputPeerChannel?> GetInputPeerChannelAsync(long channelId)
```

Async version of `TelegramChannelsResenderService.GetInputPeerChannel` (line 849):
- Call `_client.Messages_GetAllChats()` (async)
- Find `Channel` by `id == -channelId - 1000000000000`
- Return `new InputPeerChannel(channel.id, channel.access_hash)` or `null`

### 2. Extract `ProcessAlbumMessagesAsync` from `FlushAlbumAsync`

Extract lines 609-701 of `FlushAlbumAsync` (the DB + send + state update logic) into:
```csharp
private async Task ProcessAlbumMessagesAsync(List<TLMessage> messages, long telegramChannelId)
```

`FlushAlbumAsync` becomes: remove buffer → dispose timer → call `ProcessAlbumMessagesAsync`.
Catch-up calls `ProcessAlbumMessagesAsync` directly (no debounce needed for historical messages).

### 3. Add `CatchUpMissedMessagesAsync`

```csharp
private async Task CatchUpMissedMessagesAsync(CancellationToken cancellationToken)
```

**Logic per channel:**
1. Load `LastProcessedMessageId` from `TelegramDiscordChannelStates`
2. Get `InputPeerChannel` via `GetInputPeerChannelAsync`
3. **Paginate** with `Messages_GetHistory` (limit=100 per page):
   - Fetch newest messages first
   - Collect all `TLMessage` with `ID > LastProcessedMessageId`
   - Stop when a batch returns 0 qualifying messages (reached known state) or batch is empty
4. Sort collected messages by ID ascending
5. Split into:
   - **Albums**: group by `grouped_id` (non-zero), process each group as album
   - **Singles**: process individually
6. **1-minute cooldown** (`Task.Delay(TimeSpan.FromMinutes(1), cancellationToken)`) between each send operation (each single message or each album batch)
7. State update happens inside `ProcessSingleMessageAsync` / `ProcessAlbumMessagesAsync` (existing logic)

**Pagination detail** (same pattern as `TelegramChannelsResenderService` line 125):
```csharp
var messages = await _client.Messages_GetHistory(
    peer: inputPeer,
    offset_id: 0,        // fetch from newest
    add_offset: 0,
    limit: 100
);
```
For subsequent pages, use the smallest message ID from the previous batch as `offset_id`.

**Per-channel isolation:** try/catch per channel, log error, continue to next.

### 4. Integration in `InitializeAsync`

After `_client.OnUpdates += OnUpdatesReceived`:
```csharp
_ = Task.Run(() => CatchUpMissedMessagesAsync(cancellationToken), cancellationToken);
```

Fire-and-forget so `OnUpdates` starts immediately. Deduplication via `CheckAndUpdateStateAsync` ensures no double-processing.

### 5. Cooldown implementation

Between each send (single message or album batch):
```csharp
if (!cancellationToken.IsCancellationRequested)
{
    await Task.Delay(TimeSpan.FromMinutes(1), cancellationToken);
}
```

This applies only during catch-up, not during live processing.
