# Plan: Silent message validation errors, loud redemption errors

## Goal
Validation errors for redemption (ChannelPointsCustomRewardRedemption) events should be displayed in chat. Validation errors for message (OnMessage) events should be silently ignored — no chat output.

## Current state
All services call `ValidateWithResponseAsync(userName)` which sends loud validation errors to chat. Two terminal methods already exist:
- `ValidateAsync()` — silent, returns result only, no chat
- `ValidateWithResponseAsync(userName)` — sends `FirstError` to chat for loud checks

## Approach
One-word change per handler: swap `.ValidateWithResponseAsync(...)` → `.ValidateAsync()` in message-based services. Redemption services stay unchanged.

## Files to modify (4 production files, 0 interface changes)

| File | Change |
|------|--------|
| `MARS.Server/Services/Twitch/Rewards/HighlitedMessage.cs` | `.ValidateWithResponseAsync(...)` → `.ValidateAsync()` |
| `MARS.Server/Services/Twitch/Rewards/TwitchMediaAlerts.cs` | **Message handler only** — same swap. Redemption handler untouched. |
| `MARS.Server/Services/Twitch/ClientMessages/TwitchAutoHello/AutoHello.cs` | `.ValidateWithResponseAsync(...)` → `.ValidateAsync()` |
| `MARS.Server/Services/Twitch/SignalRAlerts/TwitchMessagesHubAwaker.cs` | Both handlers — same swap |

## What stays unchanged

- `ValidationServiceMockHelper` — already sets up both `ValidateAsync()` and `ValidateWithResponseAsync()` for both builders
