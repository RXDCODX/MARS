# Waifu Wife Chatbot — LM-Kit.NET (RagEngine + RagChat)

## Overview

LLM-чатбот "жены-собеседника" для Twitch-зрителей. **Всё в MARS.AudioController** через LM-Kit.NET — LLM-инференс, embeddings, RAG-хранилище. Никаких внешних БД для RAG.

---

## Архитектура

```
Twitch Chat: "!жена привет, как дела?"
        │
        ▼
MARS.Server (OnMessageReceived → парсинг "!жена")
  ├─ Проверка: Husband.IsPrivated == true
  ├─ waifuName из WaifuBrideId → Waifu.Name
  │
  │  SignalR: WaifuChatMessage(twitchId, displayName, waifuName, message)
        ▼
MARS.AudioController — WaifuLlmService
  ┌──────────────────────────────────────────────────────┐
  │  LM-Kit.NET RagChat (всё в одном)                    │
  │  ├─ LLM: Qwen2.5-0.5B (каталог, автозагрузка)       │
  │  ├─ Embeddings: embeddinggemma-300m (каталог)         │
  │  ├─ RagEngine: per-viewer knowledge base              │
  │  │   └─ history: история диалогов (pgvector)          │
  │  ├─ PgVectorEmbeddingStore: PostgreSQL MARS.Server    │
  │  └─ System prompt (waifu wife persona)                │
  └──────────────────────────────────────────────────────┘
  ├─ Facts: PostgreSQL MARS.Server (WaifuChatFacts)
        │ SignalR: WaifuChatResponse(twitchId, response)
        ▼
MARS.Server → client.SendMessageToMainTwitchAsync()
```

**Триггер:** `!жена <текст>` / `!waifu <текст>`. Только женатые зрители.
**Ответ:** текст в чат. Без TTS.

---

## Почему LM-Kit.NET, а не pgvector

LM-Kit.NET имеет **встроенный `RagEngine`**:
- `RagEngine` — управление knowledge base с чанкингом и embeddings
- `RagChat` — multi-turn диалог с автоматическим RAG retrieval
- `FileSystemVectorStore` — persistence embeddings на диск (без PostgreSQL)
- `LM.LoadFromModelID("embeddinggemma-300m")` — embedding модель автозагружается
- Per-viewer изоляция — каждый зритель = отдельный `RagEngine` instance

**Не нужно:**
- REST API между AudioController и Server
- Ручная загрузка embedding модели
- `FileSystemVectorStore` (заменён на `PgVectorEmbeddingStore`)

## Модели (автозагрузка)

LM-Kit.NET скачивает модели автоматически из каталога:

| Модель | ID | Размер | Назначение |
|--------|-----|--------|------------|
| **Google Gemma 4 E2B** | `gemma4:e2b` | ~2.9 GB | Генерация ответов (MoE: 5.1B total, ~2B active) |
| EmbeddingGemma | `embeddinggemma-300m` | ~225 MB | Embeddings для RAG |

**Почему `gemma4:e2b`:**
- MoE (Mixture of Experts): 5.1B total, но только ~2B active на токен → быстро на CPU
- 140+ языков включая русский
- 128K контекст
- Apache 2.0 лицензия
- Качество значительно лучше чем Qwen2.5-0.5B

Кешируются в `%USERPROFILE%/.lm-kit/models/`. Никаких ручных загрузок.

## Шаги реализации

### Шаг 1: WaifuLlmService — RagChat per viewer

Каждый зритель получает свой `RagEngine` с facts + history. При первом сообщении создаётся, далее переиспользуется. LRU eviction для памяти.

```csharp
public class WaifuLlmService : IDisposable
{
    private readonly LM _chatModel;
    private readonly LM _embedModel;
    private readonly ConcurrentDictionary<string, RagChat> _viewerChats = new();
    private readonly ConcurrentDictionary<string, DateTime> _lastActivity = new();
    private readonly string _dataPath;
    private readonly ILogger<WaifuLlmService> _logger;
    private readonly SemaphoreSlim _inferenceLock = new(1, 1);
    private readonly ConcurrentDictionary<string, DateTime> _cooldowns = new();

    // LRU: max 50 viewer sessions in memory
    private const int MaxViewerSessions = 50;

    public WaifuLlmService(IOptions<WaifuChatOptions> options, ILogger<WaifuLlmService> logger)
    {
        _logger = logger;
        var opts = options.Value;
        _chatModel = LM.LoadFromModelID(opts.ChatModelId);    // "gemma4:e2b"
        _embedModel = LM.LoadFromModelID(opts.EmbedModelId);  // "embeddinggemma-300m"
        _dataPath = opts.DataPath;
    }

    public async Task<string?> GenerateResponseAsync(
        string twitchId, string displayName, string waifuName,
        string userMessage, CancellationToken ct = default)
    {
        if (IsOnCooldown(twitchId)) return null;

        await _inferenceLock.WaitAsync(ct);
        try
        {
            EvictStaleSessions();

            var chat = _viewerChats.GetOrAdd(twitchId, id =>
            {
                var storePath = Path.Combine(_dataPath, id);
                var store = new FileSystemVectorStore(storePath);
                var ragEngine = new RagEngine(_embedModel, store);

                return new RagChat(ragEngine, _chatModel)
                {
                    MaxRetrievedPartitions = 5,
                    MinRelevanceScore = 0.3f,
                    SystemPrompt = BuildSystemPrompt(waifuName, displayName),
                };
            });

            _lastActivity[twitchId] = DateTime.UtcNow;

            // RagChat.Submit() синхронный, блокирующий → Task.Factory.StartNew LongRunning
            var result = await Task.Factory.StartNew(
                () => chat.Submit(userMessage, ct),
                ct,
                TaskCreationOptions.LongRunning,
                TaskScheduler.Default);

            SetCooldown(twitchId);
            return result.Completion.Trim();
        }
        catch (Exception ex)
        {
            _logger.LogError(ex, "LLM error for {TwitchId}", twitchId);
            return null;
        }
        finally
        {
            _inferenceLock.Release();
        }
    }
}
```

## Как формируются факты о зрителе

### Два уровня памяти

**Уровень 1 — Embeddings (автоматически, каждый сообщение):**
LM-Kit `RagEngine` автоматически векторизует каждое сообщение и сохраняет в `FileSystemVectorStore`. При повторном обращении зрителья `RagChat` семантически ищет релевантные прошлые сообщения и подставляет в контекст. Работает "из коробки", без дополнительного кода.

**Уровень 2 — Explicit Facts (каждые N сообщений, отдельный LLM вызов):**
Каждые 5 сообщений (настраивается) — дополнительный LLM вызов для извлечения ключевых фактов. Это короткий, быстрый промпт:

```
Из этого диалога извлеки факты о собеседнике (имя, хобби, предпочтения, важные детали).
Верни только список фактов, по одному на строку. Если новых фактов нет — верни "нет".
Диалог:
Пользователь: Привет, я Коля, играю в Valorant
Жена: Привет Коля! Какая у тебя ранг?
Пользователь: Алмаз
```

**Ответ LLM:**
```
Имя: Коля
Играет в Valorant
Ранг: Алмаз
```

### Что попадает в факты

| Тип | Пример | Источник |
|-----|--------|----------|
| Имя | "Зовут Коля" | Зритель представился |
| Хобби | "Играет в Valorant" | Упомянул в разговоре |
| Предпочтения | "Любит пиццу" | Сказал в чате |
| Ранг/статус | "Ранг Алмаз в Valorant" | Уточнил |
| Семья | "У него кот Барсик" | Рассказал |
| Отношения | "Любит свою жену Мику" | Взаимодействие с WaifuRoll |

### Flow извлечения фактов

**Основной flow (во время стрима):**
```
Зритель пишет сообщение
        │
        ▼
WaifuLlmService.GenerateResponseAsync()
  ├─ 1. RagChat.Submit() → ответ зрителю
  ├─ 2. Сообщения автоматически сохраняются в FileSystemVectorStore (embeddings)
  └─ 3. Вернуть ответ зрителю
  (без LLM вызова для фактов — это делается в фоне)
```

**Фоновый flow (стрим оффлайн):**
```
WaifuChatCleanupService (каждые 10 мин)
  ├─ Проверить: стрим оффлайн?
  ├─ Да → для каждой сессии:
  │     ├─ LLM: "Извлеки факты из истории"
  │     ├─ SignalR → MARS.Server → PostgreSQL (upsert facts)
  │     └─ Dispose сессию (освободить память)
  └─ Нет → пропустить
```

### При старте новой сессии

Когда зритель пишет после LRU eviction или перезапуска:
1. `RagChat` пересоздаётся (embeddings загружаются с диска)
2. Факты загружаются из PostgreSQL через SignalR → MARS.Server
3. Факты инжектятся в `SystemPrompt`:
```
## Что ты знаешь о своём муже:
- Зовут Коля
- Играет в Valorant, ранг Алмаз
- У него кот Барсик
```

### Фоновая задача: WaifuChatCleanupService

Когда стрим не включён — отдельный `BackgroundService` извлекает факты и освобождает память.

```csharp
public class WaifuChatCleanupService : BackgroundService
{
    private readonly WaifuLlmService _llmService;
    private readonly IStreamStateProvider _streamState; // проверка: стрим онлайн?

    protected override async Task ExecuteAsync(CancellationToken stoppingToken)
    {
        while (!stoppingToken.IsCancellationRequested)
        {
            await Task.Delay(TimeSpan.FromMinutes(10), stoppingToken);

            if (!_streamState.IsOnline)
            {
                // Стрим оффлайн — извлекаем факты из всех активных сессий
                await _llmService.ExtractAndSaveAllFactsAsync(stoppingToken);

                // Очищаем сессии из памяти (embeddings остаются на диске)
                _llmService.DisposeAllSessions();
            }
        }
    }
}
```

**WaifuLlmService — метод для фоновой задачи:**
```csharp
public async Task ExtractAndSaveAllFactsAsync(CancellationToken ct)
{
    foreach (var (twitchId, chat) in _viewerChats)
    {
        try
        {
            // LLM вызов: "Извлеки факты из всей истории диалога"
            var history = chat.ChatHistory; // все сообщения сессии
            var facts = await ExtractFactsFromHistory(twitchId, history, ct);

            // Сохранить в PostgreSQL через SignalR
            foreach (var fact in facts)
            {
                await _ragService.StoreFactAsync(twitchId, fact, ct);
            }
        }
        catch (Exception ex)
        {
            _logger.LogWarning(ex, "Failed to extract facts for {TwitchId}", twitchId);
        }
    }
}

public void DisposeAllSessions()
{
    foreach (var chat in _viewerChats.Values)
        chat.Dispose();
    _viewerChats.Clear();
    _lastActivity.Clear();
}
```

**Плюсы:**
- Нет задержки при общении (факты извлекаются в фоне, не во время чата)
- При перезапуске стрима все зрители получают "жену" которая помнит их
- Память освобождается когда стрим оффлайн
- Факты извлекаются из полной истории, а не по 5 сообщений (качество лучше)

**Минусы:**
- Если стрим не выключается днями — факты не извлекаются до оффлайна
- Нужен механизм определения "стрим оффлайн" (проверять `StreamState` в MARS.Server)

## Fix: RagEngine пуст при первом использовании + PgVectorEmbeddingStore

**Ошибка:** `The RAG engine has no data sources. Import data before submitting queries.`

**Причина:** `RagChat.Submit()` требует хотя бы один data source. `FileSystemVectorStore` пуст при первом использовании.

**Решение:** Использовать `PgVectorEmbeddingStore` из `LM-Kit.NET.Data.Connectors.PgVector` — готовый коннектор к pgvector. Работает с существующей PostgreSQL БД MARS.Server.

### Как работает PgVectorEmbeddingStore

```csharp
// Подключение к существующей PostgreSQL с отдельной схемой
var store = new PgVectorEmbeddingStore(connectionString, schema: "waifu_chat");
// Или через NpgsqlDataSource
var store = new PgVectorEmbeddingStore(npgsqlDataSource, schema: "waifu_chat");

// Создаёт таблицы в схеме waifu_chat: id text PK, embedding vector(N), metadata jsonb
// Автоматически вызывает CREATE EXTENSION IF NOT EXISTS vector
// Автоматически создаёт схему если не существует
// Косинусное расстояние через <=> оператор
```

**НЕ нужен EF DbContext для embeddings.** `PgVectorEmbeddingStore` использует raw Npgsql и сам управляет схемой. EF Core используется только для `WaifuChatFacts` (обычная таблица).

**Отдельная схема `waifu_chat`** — изолирует таблицы embeddings от основной БД MARS.Server.

## Известные риски

1. **LM-Kit.NET Community Edition** — бесплатно для некоммерческого использования. Для стрима на Twitch — допустимо.
2. **LRU eviction** — при >50 одновременных зрителей старые сессии вытесняются из памяти. При повторном обращении сессия пересоздаётся из `FileSystemVectorStore` на диске. "Жена" помнит факты (из pgsql) и embeddings (из диска), но теряет контекст последнего разговора.
3. **Sync `Submit()`** — обёрнут в `Task.Factory.StartNew(LongRunning)`, не блокирует SignalR pipeline.
4. **Размер на диске** — каждый viewer = отдельный `FileSystemVectorStore`. При 100 зрителях ~100MB.
5. **Факты извлекаются в фоне** — только когда стрим оффлайн. Если стрим идёт днями без перерыва, факты не обновятся до оффлайна.
6. **Определение "стрим оффлайн"** — нужен доступ к `StreamState` из AudioController (через SignalR или конфигурацию).

### Проблема 2: AutoHello контекст

## Обработка реплаев на AutoHello сообщения

### Проблема
Когда жена приветствует зрителя (AutoHello), зритель может ответить реплаем на это сообщение. Сейчас это не обрабатывается — ответ пропускается.

### Решение
В `WaifuChatTwitchReward.MightBeWaifuChat()` добавить проверку: если сообщение является реплаем на сообщение бота с текстом AutoHello — обрабатывать как обращение к жене.

### TwitchLib API
`ChatMessage.ChatReply` содержит:
- `ParentMsgBody` — текст родительского сообщения
- `ParentUserId` — ID автора родительского сообщения
- `ParentDisplayName` — имя автора
- `ParentMsgId` — ID родительского сообщения

### Формат AutoHello сообщений
```
@{user}, твой супруг {spouseName} прислал(а) тебе сообщение: "{helloMsg}"
```
Или:
```
@{user}, твой супруг {spouseName} поздравляет тебя с годовщиной!
```

### Логика определения
```csharp
private static bool IsReplyToBotAutoHello(ChatMessage chatMessage)
{
    var reply = chatMessage.ChatReply;
    if (reply is null) return false;

    // Проверяем что реплай на сообщение бота
    if (!string.Equals(reply.ParentUserLogin, TwitchExstension.BotName, 
            StringComparison.OrdinalIgnoreCase))
        return false;

    // Проверяем что текст содержит AutoHello паттерн
    var parentBody = reply.ParentMsgBody ?? "";
    return parentBody.Contains("прислал") 
        || parentBody.Contains("поздравляет")
        || parentBody.Contains("сообщение:");
}
```

### Обновлённый MightBeWaifuChat
```csharp
public bool MightBeWaifuChat(string message, ChatMessage? chatMessage = null)
{
    // 1. Keyword check (как раньше)
    if (TriggerKeywords.Any(kw => message.ToLowerInvariant().Contains(kw)))
        return true;
    
    // 2. Команда !жена / !waifu
    if (message.StartsWith("!жена ", ...) || message.StartsWith("!waifu ", ...))
        return true;
    
    // 3. Реплай на AutoHello сообщение бота
    if (chatMessage is not null && IsReplyToBotAutoHello(chatMessage))
        return true;
    
    return false;
}
```

## Рефакторинг: все сообщения → классификатор, keyword → skip

### Проблема
Сейчас `MightBeWaifuChat` на сервере фильтрует сообщения по ключевым словам. Сообщения без ключевых слов не доходят до AudioController. Нужно чтобы ВСЕ сообщения от женатых зрителей шли в AudioController, где классификатор решает что делать.

### Архитектура

```
Twitch Chat: "Куруми привет!" (keyword match)
        │
        ▼
WaifuChatTwitchReward (MARS.Server)
  ├─ Keyword check: содержит "Куруми" → SkipClassifier = true
  ├─ Проверка: женат? кулдаун?
  └─ SignalR → AudioController (SkipClassifier=true)
        │
        ▼
AudioControllerHubClientHostedService
  ├─ SkipClassifier → сразу в LLM (пропуск классификатора)
  └─ Ответ → Twitch

Twitch Chat: "какой сегодня день?" (нет keyword)
        │
        ▼
WaifuChatTwitchReward (MARS.Server)
  ├─ Keyword check: не содержит keyword → SkipClassifier = false
  ├─ Проверка: женат? кулдаун?
  └─ SignalR → AudioController (SkipClassifier=false)
        │
        ▼
AudioControllerHubClientHostedService
  ├─ Классификатор → "general_chat" → пропуск
  └─ Нет ответа
```

### Изменения

**1. WaifuChatMessage — добавить `SkipClassifier`:**
```csharp
public bool SkipClassifier { get; set; }
```

**2. WaifuChatTwitchReward — убрать `MightBeWaifuChat`, отправлять все сообщения:**
```csharp
// Было: if (!MightBeWaifuChat(message, e.ChatMessage)) return;

// Стало: все сообщения от женатых зрителей идут в AudioController
var isKeywordMatch = TriggerKeywords.Any(kw => message.Contains(kw))
    || message.StartsWith("!жена ") || message.StartsWith("!waifu ");

await hubContext.Clients.All.WaifuChatMessage(new WaifuChatMessage
{
    // ...
    SkipClassifier = isKeywordMatch,
});
```

**3. AudioControllerHubClientHostedService — проверять SkipClassifier:**
```csharp
// Было: классификатор проверяет все сообщения
// Стало: если SkipClassifier — сразу в LLM, иначе через классификатор
if (msg.SkipClassifier)
{
    _logger.LogInformation("[WaifuChat] SkipClassifier=true — direct to LLM");
}
else if (_classifier is not null)
{
    var classification = _classifier.Classify(msg.Message);
    if (!classification.IsWaifuChat)
    {
        _logger.LogInformation("[WaifuChat] Classified as {Category} — skipping", ...);
        return;
    }
}
```

**4. WaifuChatClassifier — расширить промпт с TriggerKeywords:**
```csharp
private const string ClassificationGuidance = """
    Определи, является ли сообщение обращением к партнёру/супругу.

    жена, wife, муж, husband, супруг, spouse, партнёр, partner, половинка,
    милая, милый, дорогая, дорогой, любимая, любимый, котик, солнце, зайка

    - Прямое имя персонажа
    - Вопросы/просьбы к партнёру
    - Комплименты, ревность

    """;
```

1. `IgnoredUsers` — дублирует `SkipBlacklisted()` из validator
2. AutoHello определение через паттерн `"прислал"` — ненадёжно
3. Текст AutoHello не передаётся в LLM при реплае

### Решение

**1. Удалить `IgnoredUsers`** — `SkipBlacklisted()` уже проверяет чёрный список.

**2. Упростить `IsReplyToBotAutoHello`** — проверять `ChatReply.ParentUserLogin` на имя бота:

```csharp
private static bool IsReplyToBotAutoHello(ChatMessage chatMessage)
{
    var reply = chatMessage.ChatReply;
    if (reply is null) return false;
    return string.Equals(reply.ParentUserLogin, TwitchExstension.BotName,
        StringComparison.OrdinalIgnoreCase);
}
```

**3. Текст AutoHello из `ChatReply.ParentMsgBody`** — TwitchLib уже хранит текст родительского сообщения. Не нужно отслеживать ID сообщений.

**4. Обновить `GetAutoHelloContextAsync`:**

```csharp
if (IsReplyToBotAutoHello(chatMessage))
{
    var parentBody = chatMessage.ChatReply!.ParentMsgBody ?? "";
    return $"Муж ответил на твоё сообщение: \"{parentBody}\"";
}
```

## Дообучить классификатор через LoRA Fine-tuning

### Проблема
Классификатор не распознает обращения без ключевых слов ("любимка, давай обсудим").

### Решение
Использовать LM-Kit `LoraFinetuning` для дообучения маленькой модели на реальных примерах.

### Pipeline сбора данных

1. Keyword match → `"любимка, давай обсудим"` → waifu_chat (positive example)
2. Нет keyword → `"какой сегодня день?"` → general_chat (negative example)
3. Сохраняем в PostgreSQL: `WaifuChatTrainingSample`
4. При накоплении 100+ примеров → запускаем fine-tuning
5. Обучаем LoRA adapter → загружаем в классификатор

### Training data формат (ShareGPT)

```json
[
  {"from": "human", "value": "любимка, давай обсудим"},
  {"from": "assistant", "value": "waifu_chat"},
  {"from": "human", "value": "какой сегодня день?"},
  {"from": "assistant", "value": "general_chat"}
]
```

### LoRA Fine-tuning код

```csharp
using LMKit.Model;
using LMKit.Finetuning;

var model = LM.LoadFromModelID("gemma3:270m");

using var finetuning = new LoraFinetuning(model);
finetuning.Parameters.Rank = 16;
finetuning.Parameters.Alpha = 32;
finetuning.Parameters.Epochs = 4;
finetuning.Parameters.LearningRate = 1e-4f;

foreach (var (message, label) in trainingData)
{
    var sample = new ChatHistory(model);
    sample.AddMessage(AuthorRole.User, message);
    sample.AddMessage(AuthorRole.Assistant, label);
    finetuning.AddTrainingData(sample);
}

finetuning.TrainToAdapter("adapters/waifu-classifier.gguf");
model.ApplyLoraAdapter(new LoraAdapterSource("adapters/waifu-classifier.gguf"));
```

### Файлы
- `MARS.Server/Services/WaifuRoll/Entitys/WaifuChatTrainingSample.cs` — EF entity
- `MARS.Server/DataBaseContext/AppDbContext.cs` — DbSet
- `MARS.AudioController/Services/WaifuChat/WaifuChatFineTuner.cs` — LoRA trainer
- `MARS.AudioController/Services/WaifuChat/WaifuChatClassifier.cs` — использовать fine-tuned adapter
