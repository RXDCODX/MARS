# Fix: PyroAlerts double-fetch in StrictMode + setState in effect

## Problem 1: Double-fetch in StrictMode
React StrictMode mounts/unmounts/remounts components in dev mode. The `<source src={...}>` element triggers a browser fetch on each mount. The server (`PyroAlerts.cs`) deletes the file from `MemoryStorage` after serving it once → second request gets 400.

## Problem 2: setState in effect (already fixed)
`setCurrentHighPriority` was called inside `useEffect` body. Fixed by deriving `currentHighPriority` from `highPriorityQueue[0]`.

## Solution for Problem 1: Blob URL caching + AbortController

### Changes to `MARS.Projects/mars.client/src/components/OBS_Components/PyroAlerts/Primitive/Audio.tsx`

1. **Add module-level cache** (`Map<string, string>`) to store blob URLs by file path
   - Shared across component instances and survives StrictMode unmount/remount
   - Second mount reuses cached blob URL instead of re-fetching

2. **Add `useEffect` to fetch audio as blob**:
   - `useMemo` creates a fetch promise (cached at module level by URL)
   - `useEffect` awaits it, creates `URL.createObjectURL(blob)`, stores in state
   - `AbortController` aborts the in-flight fetch on StrictMode unmount (prevents wasted work)
   - Cleanup revokes blob URL

3. **Replace `<source src={fileInfo.filePath}>` with `src={blobUrl}` on `<audio>`**

4. **Add loading state** — show nothing until blob is ready

5. **Add `onError` handler** — revoke blob URL on cache cleanup

### Cache lifecycle
- Cache grows during session (one entry per unique audio URL)
- Acceptable: audio files are small, entries are few per session
- Blob URLs are revoked on unmount (memory reclaimed), but cache entry persists for reuse

### StrictMode flow
1. First mount: fetch starts → promise cached in module Map → StrictMode unmounts → AbortController.abort() → cleanup runs
2. Remount: useMemo returns same cached promise → effect awaits it → blob URL already created → setState works

### Production flow (no StrictMode)
1. Single mount: fetch → blob URL → play → unmount → revoke + abort
