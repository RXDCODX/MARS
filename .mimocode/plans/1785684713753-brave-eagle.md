# Plan: Верификация реконнекта через тестовое сообщение

## Задача
Доработать `twitchchannelreconnect_command.cs` — после реконнекта отправить тестовое сообщение в Twitch-чат и подтвердить реконнект, поймав это сообщение через `ITwitchClient.OnMessageReceived`.

## Файл для изменения
`MARS.Projects/MARS.Server/Services/CommandExecutor/Commands/twitchchannelreconnect_command.cs`

## Что меняем

### 1. Добавить зависимость `ITwitchClient` в конструктор
```csharp
public class TwitchchannelreconnectCommand(
    TwitchConnectionManager manager,
    ITwitchClient client
) : BaseCommand
```
`ITwitchClient` — синглтон в DI (TwitchClientProxy), `CommandFactory` разрешит автоматически.

### 2. Изменить ExecuteAsync — добавить верификацию после реконнекта

Алгоритм:
1. `manager.ReconnectAsync()` → если `false`, сразу вернуть ошибку
2. Сгенерировать уникальный маркер (`Guid.NewGuid().ToString("N")[..8]`)
3. Подписаться на `client.OnMessageReceived` с хэндлером
4. Создать `TaskCompletionSource<bool>` с `RunContinuationsAsynchronously`
5. Отправить `reconnect_check:{marker}` через `client.SendMessageToMainTwitchAsync()`
6. Ждать `tcs.Task` с таймаутом 5 секунд (через `CancellationTokenSource`)
7. Хэндлер фильтрует по `BotName` ("catisaai") и тексту сообщения
8. В `finally` — отписаться от `OnMessageReceived`

### 3. Добавить using-ы
```csharp
using System;
using MARS.Server.Exstensions;
using TwitchLib.Client.Events;
```

## Паттерн верификации

```csharp
var marker = Guid.NewGuid().ToString("N")[..8];
var verificationMessage = $"reconnect_check:{marker}";
var tcs = new TaskCompletionSource<bool>(TaskCreationOptions.RunContinuationsAsynchronously);

Task Handler(object? sender, OnMessageReceivedArgs args)
{
    if (args.ChatMessage.Username.Equals(TwitchExstension.BotName, StringComparison.OrdinalIgnoreCase)
        && args.ChatMessage.Message == verificationMessage)
    {
        tcs.TrySetResult(true);
    }
    return Task.CompletedTask;
}

try
{
    client.OnMessageReceived += Handler;
    await client.SendMessageToMainTwitchAsync(verificationMessage);
    
    using var timeoutCts = new CancellationTokenSource(TimeSpan.FromSeconds(5));
    using var linkedCts = CancellationTokenSource.CreateLinkedTokenSource(timeoutCts.Token, cancellationToken);
    
    var received = await tcs.Task.WaitAsync(linkedCts.Token);
    return received 
        ? "Реконнект выполнен, соединение проверено" 
        : "Реконнект выполнен, но проверка не подтверждена";
}
catch (OperationCanceledException)
{
    return "Реконнект выполнен, но таймаут проверки (5 сек)";
}
finally
{
    client.OnMessageReceived -= Handler;
}
```

## Почему это работает
- `TwitchClientProxy` пересылает `OnMessageReceived` через собственное поле-событие — подписки живут после свапа клиента
- TwitchLib echo: бот получает свои собственные сообщения через `OnMessageReceived`
- Фильтр по `BotName` исключает ложные срабатывания от других пользователей
- Уникальный GUID-маркер исключает совпадение с предыдущими запусками

## Edge cases
| Сценарий | Обработка |
|---|---|
| `ReconnectAsync()` → false | Ранний возврат, сообщение не отправляется |
| Twitch не эchoит сообщение | Таймаут 5 сек → информативное сообщение |
| Вызывающий отменяет (cancellationToken) | linked CTS пробрасывает отмену |
| Гонка: сообщение пришло до `await tcs.Task` | `RunContinuationsAsynchronously` + `TrySetResult` безопасно |
| Параллельные команды реконнекта | Каждая получает свой TCS и маркер |
