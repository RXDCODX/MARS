# План: разделение DanbooruAutoPost на подсервисы + WTelegram вместо ITelegramBotClient

## Проблема

1. `DanbooruAutoPostService` — монолит: CRUD, Discord-постинг, Telegram-постинг, cron-планирование, deduplication — всё в одном классе (~960 строк)
2. Telegram-постинг использует `ITelegramBotClient` (Bot API) вместо `WTelegramClientService` (user client), который уже используется в проекте для отправки медиа (`TelegramChannelsResenderService`)
3. Bot API имеет ограничения (PHOTO_INVALID_DIMENSIONS, ограничения бота), user client — нет

## Решение

### Шаг 1: Создать подсервисы для постинга

#### 1a. `IDanbooruDiscordPoster.cs` + `DanbooruDiscordPoster.cs`

**Путь:** `Services/DanbooruAutoPost/DanbooruDiscordPoster.cs`

```csharp
public interface IDanbooruDiscordPoster
{
    Task<OperationResult> PostAsync(ulong channelId, byte[] fileBytes, string fileName, CancellationToken ct);
}

public class DanbooruDiscordPoster(IDiscordGatewayService discordGateway) : IDanbooruDiscordPoster
{
    public async Task<OperationResult> PostAsync(ulong channelId, byte[] fileBytes, string fileName, CancellationToken ct)
    {
        await using var stream = new MemoryStream(fileBytes);
        return await discordGateway.SendFileAsync(channelId, stream, fileName, null, ct);
    }
}
```

#### 1b. `IDanbooruTelegramPoster.cs` + `DanbooruTelegramPoster.cs`

**Путь:** `Services/DanbooruAutoPost/DanbooruTelegramPoster.cs`

Использует `WTelegramClientService` вместо `ITelegramBotClient`. Паттерн из `TelegramChannelsResenderService` (строки 700-746):

```csharp
public interface IDanbooruTelegramPoster
{
    Task<OperationResult> PostAsync(long chatId, byte[] fileBytes, string fileName, CancellationToken ct);
    Task<OperationResult> SchedulePostAsync(long chatId, byte[] fileBytes, string fileName, DateTime scheduleDate, CancellationToken ct);
}
```

Реализация:
1. Получить `WTelegram.Client` через `wTelegramClientService.GetClientAsync()`
2. Сконвертировать `chatId` (формат `-100XXXXXXXXXX`) в `InputPeerChannel`:
   - `actualChannelId = -chatId - 1000000000000`
   - Найти `Channel` через `client.Messages_GetAllChats()`
   - Создать `InputPeerChannel(channel.id, channel.access_hash)`
3. Загрузить файл: `await client.UploadFileAsync(stream, fileName)`
4. Отправить фото: `await client.Messages_SendMedia(peer, new InputMediaUploadedPhoto { file = inputFile }, message, Random.Shared.NextInt64())`
5. При ошибке размера — отправить как документ: `new InputMediaUploadedDocument { file = inputFile, ... }`
6. Для `SchedulePostAsync` — использовать параметр `schedule_date` в `Messages_SendMedia`:
   ```csharp
   await client.Messages_SendMedia(
       peer: inputPeer,
       media: new InputMediaUploadedPhoto { file = inputFile },
       message: caption,
       random_id: Random.Shared.NextInt64(),
       schedule_date: scheduleDate
   );
   ```

## Открытые вопросы

1. **WTelegram `Messages_SendMedia` signature**: Нужно проверить что параметр `schedule_date` доступен в v4.4.7. Если нет — использовать `messages.sendScheduledMessage` напрямую через TL schema.

2. **Deduplication для Telegram scheduled posts**: Текущий `IDeduplicationService` работает с `ulong DiscordChannelId`. Для Telegram scheduled posts deduplication не нужна (Telegram сам планирует), но для `PostImageAsync` (из `ProcessScheduledPostsAsync`) — нужна.

3. **PostImageAsync загружает файл**: Текущий `PostImageAsync` скачивает файл один раз и передаёт в подсервис. Для `TriggerNowAsync` с Telegram нужно скачивать отдельный файл для каждого слота (разные посты).
