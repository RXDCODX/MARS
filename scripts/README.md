# Скрипты репозитория

Обёртки над командами, которые в этом проекте иначе набираются руками и
повторяются с мелкими отличиями. Ничего нового они не делают: те же
`dotnet build`, `dotnet test`, `docker compose`, CSharpier и покрытие — только
с проверками, о которых забывают чаще всего, и с честными сообщениями вместо
«не удаётся выполнить».

Каждое действие существует на обеих платформах, имена совпадают: `build` =
`build.ps1` = `build.sh`. Набор имён проверяется тестом
`tests/MARS.Gateway.Tests/ScriptsParityTests.cs` — иначе расхождение двух
платформ было бы тихим.

```text
scripts/
  windows/   PowerShell 5.1 (то, что стоит в Windows из коробки)
  unix/      bash 3.2+ (то, что стоит в macOS по умолчанию)
```

Скрипты зовутся из любого каталога: корень репозитория ищется от каталога
самого скрипта, а не берётся из текущего каталога. Абсолютных путей машины в
них нет — это тоже проверяется тестом.

## Карта

| Скрипт | Что делает | Когда нужен |
|---|---|---|
| `build` | `restore`, `build` (по умолчанию) и `publish` одного сервиса | перед пушем и в CI-подобном прогоне |
| `test` | тесты с фильтрами Microsoft.Testing.Platform, по одному проекту или всем | итерация над тестом и полный прогон |
| `verify` | гейт перед пушем: формат → сборка Release → тесты | ровно то, что требует `AGENTS.md` перед `git push` |
| `format` | `dotnet csharpier format` / `check` | формат обязателен перед пушем |
| `frontend` | оба фронтенда: Yarn 4 для клиента шлюза, npm для страницы хранилища | менялся клиент |
| `e2e` | стенд целиком и навигационные тесты клиента на Playwright | проверка, что стенд живой |
| `coverage` | локальный замер покрытия тем же путём, что CI | ответ на вопрос «покрыли ли мы сервис X» |
| `release` | образы релиза: список, сборка, публикация, тег версии | подготовка релиза |
| `stack` | стенд на docker compose: up/down/logs/restart | повседневная работа со стендом |
| `migrate` | миграции EF Core: add/remove/update/script/list | изменение схемы БД сервиса |
| `clean` | уборка артефактов сборки и мусора тестовых контейнеров | после прогонов |
| `sweep` | поиск хвостов по старому имени, переменной или порту | после переименования или выпиливания |
| `pr` | ветка → гейт → пуш → PR через `gh` | конец задачи |

`common` в каждой паре — общий код платформы: поиск корня, вывод, запуск
внешних команд, список тестовых проектов, чтение матрицы публикации, выбор
файла окружения и его создания из шаблона, поиск по файлам. Подключается, а не
запускается.

Файл окружения выбирается тем же переключателем `-Dev`, что и compose-файл:
`--env-file .env.development` вместе с `docker-compose.dev.yml`
(`ASPNETCORE_ENVIRONMENT=Development`) и `--env-file .env.production` вместе с
`docker-compose.yml` (`Production`). Отдельного переключателя профиля нет
намеренно: два переключателя подряд разъедутся молча, а секреты среды обязаны
соответствовать той же среде, что и `appsettings`.

Файл создаётся из `.env.<среда>.example`, а пока такого шаблона в репозитории нет —
из `.env.example`, с предупреждением: значения там стендовые. Существующий файл
не перезаписывается никогда.

## Windows

```powershell
# полный гейт перед пушем
.\scripts\windows\verify.ps1

# сборка всего решения в Release
.\scripts\windows\build.ps1

# один тестовый проект, один класс (именно так, а не --filter)
.\scripts\windows\test.ps1 -Project MARS.Shared.Tests -FilterClass "*HealthCheck*"

# все проекты, восемь параллельно
.\scripts\windows\test.ps1 -MaxParallel 8

# клиент: типы и тесты
.\scripts\windows\frontend.ps1 -Client gateway -Action Check

# стенд, затем логи одного сервиса
.\scripts\windows\stack.ps1 -Action Up
.\scripts\windows\stack.ps1 -Action Logs -Service gateway

# что публикуется
.\scripts\windows\release.ps1 -Action List

# покрытие по одному сервису, без проверки порога
.\scripts\windows\coverage.ps1 -Project MARS.OBS.Tests -NoGate

# хвосты после переименования
.\scripts\windows\sweep.ps1 -Term SEQ_ADMIN_PASSWORD
```

Справка по любому скрипту — в его шапке: `Get-Content .\scripts\windows\build.ps1 -TotalCount 40`
(для bash та же шапка печатается опцией `--help`).

## Unix

```bash
# полный гейт перед пушем
./scripts/unix/verify.sh

# сборка всего решения в Release
./scripts/unix/build.sh

# один тестовый проект, один класс (именно так, а не --filter)
./scripts/unix/test.sh --project MARS.Shared.Tests --filter-class '*HealthCheck*'

# все проекты, восемь параллельно
./scripts/unix/test.sh --parallel 8

# клиент: типы и тесты
./scripts/unix/frontend.sh --client gateway --action check

# стенд, затем логи одного сервиса
./scripts/unix/stack.sh --action up
./scripts/unix/stack.sh --action logs --service gateway

# что публикуется
./scripts/unix/release.sh --action list

# покрытие по одному сервису, без проверки порога
./scripts/unix/coverage.sh --project MARS.OBS.Tests --no-gate

# хвосты после переименования
./scripts/unix/sweep.sh --term SEQ_ADMIN_PASSWORD
```

## Отличия платформ, о которых стоит знать

- **PowerShell 5.1 против bash 3.2.** Ни в одной из версий нет синтаксиса,
  которого не было бы в соответствующей старой оболочке: в Windows это 5.1
  (Server 2016/2019, где PowerShell 7 может не стоять), в unix — 3.2 (macOS).
  Отсюда и ручной разбор аргументов, и отсутствие ассоциативных массивов.
- **Тесты по умолчанию идут по очереди.** Каждый проект с базой поднимает свой
  контейнер Testcontainers, и параллельный прогон решения на одной машине
  заканчивался сообщением `[FATAL ERROR] Foreground threads were left running,
  forcing process exit` — при нуле красных тестов и коде возврата 1. CI так не
  делает: там по одному проекту на задачу. Параллельный режим (`-MaxParallel`,
  `--parallel`) остаётся для быстрых проектов без базы.
- **Покрытие.** `scripts/windows/coverage.ps1` только передаёт параметры
  каноническому `.github/scripts/coverage-local.ps1`: вторая реализация того же
  пути разошлась бы с CI при первом изменении фильтра, и разошлась бы молча —
  обе напечатали бы правдоподобный процент. На unix канонического скрипта нет,
  поэтому `scripts/unix/coverage.sh` повторяет его шаги, а тест сверяет
  значения фильтров с `.github/scripts/coverage-local.ps1`.
- **Права на `.sh`.** Git хранит бит исполнения отдельно от содержимого, а на
  Windows его обычно не выставляет. Если после `git add` файл добавился как
  `100644`, поставьте бит явно:

  ```bash
  git update-index --chmod=+x scripts/unix/*.sh
  ```

- **Docker Desktop на Windows и `--network host`.** `e2e.ps1` и `e2e.sh` запускают
  контейнер с `--network host`, иначе контейнер не увидит Gateway на localhost
  раннера. На Docker Desktop для Windows опция «Host networking» выключена по
  умолчанию (Settings → Resources → Network); без неё фикстура честно
  сообщит, что стенд не отвечает.
- **Цвета.** Оба скрипта гасят вывод без терминала и по `NO_COLOR`, поэтому в
  логе CI и в перенаправленном файле escape-последовательностей нет.

## Что скрипты не делают

- Не коммитит и не мержит: коммит — логический шаг, который решает человек, а
  merge — решение владельца (`pr` открывает PR и на этом останавливается).
- Не публикует образы без явного `-Push` / `--push`.
- Не удаляет чужие docker-тома: `clean` показывает висящие тома и удаляет
  только контейнеры с метками `testcontainers`.
- Не перезаписывает файл окружения: существующий `.env.production` (или
  `.env.development`) в нём держит настоящие секреты стенда, а создаётся он
  только если его нет — из шаблона своей среды.

## Договорённости, которые проверяются тестом

`tests/MARS.Gateway.Tests/ScriptsParityTests.cs` закрывает то, что иначе
разъезжается молча: одинаковый набор действий на обеих платформах, поиск корня
репозитория от каталога скрипта, отсутствие путей конкретной машины, синтаксис
MTP-фильтров, совпадение фильтров покрытия с каноническими, чтение списка
образов из `release-microservices.yml` и отсутствие merge/push без явного
указания.
