# Локальный каталог MediaStorage: путь, URL и Git

MediaStorage использует три разных значения. Их нельзя подставлять друг вместо друга.

| Значение | Пример | Для чего |
| --- | --- | --- |
| Путь на Windows | `D:/MARS/Media/wwwroot` | Источник bind mount Docker |
| Путь внутри контейнера | `/app/wwwroot/Alerts/bell.wav` | Физическое расположение файла для сервисов |
| Публичный URL | `/Alerts/bell.wav` | Ссылка, которую использует браузер и оверлей |
| Git remote | `https://github.com/RXDCODX/random-memes.git` | Удалённый репозиторий для коммитов и push |

## Настройка локального каталога

В `.env.development` или `.env.production` задаётся:

```dotenv
MEDIA_STORAGE_HOST_PATH=D:/MARS/Media/wwwroot
```

Значение должно указывать на **корень webroot**, то есть на каталог, внутри которого находятся `Alerts/`, `faces/` и остальные папки. Не указывайте URL и не указывайте саму папку `Alerts`, если она является дочерним каталогом этого корня.

Один и тот же bind mount подключается к `/app/wwwroot` у трёх контейнеров: `obs`, `alerts` и `media-storage`. В dev compose для этих сервисов также задан `ASPNETCORE_WEBROOT=/app/wwwroot`, поэтому все они используют один физический каталог, несмотря на то что исходный код смонтирован в `/src`.

Если переменная пустая, production compose продолжает использовать именованный Docker volume `mars-wwwroot`. В dev compose пустое значение по умолчанию направляется в `./data/local-wwwroot`.

На Windows используйте прямые слеши в пути (`D:/...`). Убедитесь, что диск доступен Docker Desktop и разрешён для bind mounts.

**Перед первым переключением** скопируйте содержимое прежнего `mars-wwwroot` в новый локальный каталог. Bind mount скрывает содержимое тома под точкой монтирования; Docker не объединяет две папки и не переносит файлы автоматически.

## Почему URL не меняется

В базе и файловых операциях хранится относительный путь, например `Alerts/bell.wav`. MediaStorage раздаёт его как статический файл из webroot, а Gateway проксирует маршрут `/Alerts/{**remainder}` к MediaStorage. Поэтому публичная ссылка остаётся:

```text
https://<адрес-Gateway>/Alerts/bell.wav
```

Путь `D:/MARS/Media/wwwroot` никогда не должен попадать в базу, HTML или URL. Он нужен только Docker для подключения каталога к контейнерам.

## Выборочная синхронизация с Git

Git остаётся независимым от bind mount. Настройки remote:

```dotenv
MEDIA_GIT_ENABLED=true
MEDIA_GIT_REPOSITORY_URL=https://github.com/RXDCODX/random-memes.git
MEDIA_GIT_BRANCH=master
MEDIA_GIT_USERNAME=
MEDIA_GIT_TOKEN=<токен с Contents: Read and write>
```

Корнем Git-репозитория является тот же webroot (`/app/wwwroot`). После включения Git в UI MediaStorage можно нажать «Индексировать», выделить нужные записи и нажать «Синхронизировать в Git». В коммит попадут только выбранные файлы.

Обычные операции MediaStorage также передают Git точные пути: загрузка, перемещение, удаление в корзину, восстановление и очистка корзины не должны коммитить посторонние изменения других файлов из общего каталога.

Файлы, которые Alerts/OBS записали напрямую в папку, не попадают в Git автоматически при каждом изменении. Их можно зарегистрировать кнопкой «Индексировать», а затем выбрать и синхронизировать в UI.

Git-синхронизация выполняет commit и push. Она не является постоянным двусторонним зеркалом: изменения, сделанные непосредственно в удалённом репозитории после инициализации локальной рабочей копии, автоматически не подтягиваются.
